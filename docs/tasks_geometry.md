**One-point-per-sequence tasks**: `geometry_lid`, `geometry_intrinsic_dim`
(layerwise mode), `geometry_vendi_score`, `geometry_magnitude`,
`geometry_correlation_dimension`, `geometry_gride`,
`geometry_information_imbalance`, `geometry_neighborhood_overlap` and
`geometry_alpha_req` read one point per sequence: the last token of a 20-word
window cut from each passage at a hashed offset
(`src/blme/tasks/_windows.py`), the same words for every model, with 1000
sequences. Whole passages are opt-in (`points_readout: passage`).

**Sink rows** (`TOKEN_POLICY = "exclude_sinks"`): token clouds and pools drop position 0 and every token whose hidden-state norm exceeds 10x its document's median token norm at any interior depth (the union over depths; `_meta_sink_factor`, `_meta_sink_n_depths`, `_meta_sink_n_massive_dropped`). On models without massive activations only position 0 is dropped.

**Size-invariance declarations**: each section lists the keys its task
declares in `SIZE_INVARIANT`, the transformations they are declared invariant
to, and the test that backs the declaration. Identity-block invariance is
declared per placement (interior, leading, trailing). A key that is not listed
makes no such claim.

**Paper-faithful vs. BLME notes**: IsoScore uses the Rudman et al.
covariance-isotropy score (`arXiv:2108.07344`). `geometry_hsic` implements
HSIC dependence, not a KDE mutual-information estimator.
`geometry_prediction_alignment`, `geometry_categories`,
`geometry_representation_sensitivity`, `geometry_positional_decay`,
`geometry_lipschitz` and `geometry_weight_norms` are BLME diagnostics without
a single canonical paper. `geometry_categories` is not cross-model comparable.
`geometry_tokenizer_efficiency` reports tokenizer properties; these are
confounds and efficiency diagnostics, not standalone proof of downstream
quality.

## 1. Local Intrinsic Dimensionality (LID)
* **What are we measuring**: The local degrees of freedom of the representation manifold around a specific point.
* **How are we measuring**: Ma et al.'s (2018, Eq. 4) maximum-likelihood estimate, -k / sum_i log(r_i / r_k) over the `k: 20` nearest neighbours, on one point per sequence: the last token of a 20-word window cut from each passage at a hashed offset (the same words for every model), with `num_samples: 1000`. Neighbours are drawn from the other sequences.
* **Hypothesis**: Models with excessively high LID might suffer from the curse of dimensionality and overfitting, while very low LID implies over-compression.
* **Citation/Paper**: `Levina, E. & Bickel, P. J. (2004). Maximum Likelihood Estimation of Intrinsic Dimension.` [NeurIPS 2004]. Secondary: `Ma, X., et al. (2018). Characterizing Adversarial Subspaces Using Local Intrinsic Dimensionality.` [ICLR 2018]
* **File & Function**: `src/blme/tasks/geometry/lid.py` -> `LocalIntrinsicDimensionalityTask`
* **Critical Info**: Headline keys: `lid_mean`, `lid_std`, `lid_max`, `lid_median`, `lid_first_layer`, `lid_mid_layer`. Declared invariant: `lid_mean`, `lid_std`, `lid_max`, `lid_median` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_lid.py::test_width_scale_and_depth_invariant`); `lid_first_layer` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, trailing) (`tests/tasks/invariance/test_geometry_lid.py::test_width_scale_and_depth_invariant`). The estimate falls as the reference set grows, so N is the same 1000 sequences for every model. Exact-duplicate neighbours give a 0.0 estimate that is kept in the mean, as in the released `mle_batch`; the minimum is `_meta_` for that reason. The token-cloud value (every token of `token_cloud_docs: 200` documents, position 0 and massive-activation rows excluded) is reported as `_meta_tokens_*`. Whole passages are opt-in (`points_readout: passage`).
* **Paper summary**: Levina & Bickel derive the MLE of intrinsic dimension from nearest-neighbor distances by modeling them as a Poisson process (their canonical form sums to k−1). Ma et al. adapt it (the −k variant, their Eq. 4) to characterize adversarial subspaces, showing LID rises sharply for adversarial examples. BLME implements Ma et al.'s -k variant per point and summarises it by mean, standard deviation, median and maximum.

## 2. Residual Relative Change (`geometry_lipschitz`)
* **What are we measuring**: How much each block rewrites the residual stream, as a fraction of its size.
* **How are we measuring**: Per block, the relative change ‖h_(l+1) - h_l‖ / ‖h_l‖ averaged over tokens, with sink rows (position 0 and massive-activation tokens) excluded at every layer. The headlines are depth-additive: `e2e_log_norm_growth` (the telescoping log norm growth), `total_angular_path` (the sum of per-block angles), the maximum per-block relative change, and the embedding -> block 0 update reported on its own.
* **Hypothesis**: Blocks that rewrite a large fraction of the residual stream apply large updates; a small total path indicates a nearly straight residual trajectory. This is a descriptive profile, not a stability bound.
* **Citation/Paper**: `Anil, C., Lucas, J., & Grosse, R. (2019). Sorting out Lipschitz function approximation.` [ICML 2019, ArXiv: 1811.05381]. Related estimation work: `Miyato, T., et al. (2018). Spectral Normalization for Generative Adversarial Networks.` and `Scaman, K. & Virmaux, A. (2018). Lipschitz regularity of deep neural networks.` [NeurIPS 2018, ArXiv: 1805.10965]
* **File & Function**: `src/blme/tasks/geometry/lipschitz.py` -> `LipschitzContinuityTask`
* **Critical Info**: Headline keys: `e2e_log_norm_growth`, `total_angular_path`, `relative_change_max`, `embedding_relative_change`. Declared invariant: `e2e_log_norm_growth`, `total_angular_path`, `relative_change_max` to identity blocks (interior, trailing) (`tests/tasks/invariance/test_geometry_lipschitz.py::test_depth_additive_keys_invariant_under_identity_insertion`). This is a BLME construct and not a Lipschitz estimate: the cited papers bound Jacobian operator norms, which are not defined on observed token states. A uniform mean over blocks falls as L / (L + n) under n inserted identity blocks, which is why the headlines are depth-additive; an identity block before block 0 is not covered. Defaults: `num_samples: 20`.

## 3. Representational Similarity Analysis (RSA)
* **What are we measuring**: The structural isomorphism between the representation spaces of two different models, or two different layers.
* **How are we measuring**: Tokens are the conditions: `max_tokens: 200` rows spaced evenly over the corpus, sink rows excluded, give one Representational Dissimilarity Matrix per layer (correlation distance). RDMs are compared by Spearman rank correlation of their upper triangles. The headlines are the minimum over adjacent layers and the first-last pair.
* **Hypothesis**: Two networks might have different exact geometries but computationally identical relative similarity structures. RSA allows comparison across models with different hidden dimensions.
* **Citation/Paper**: `Kriegeskorte, N., Mur, M., & Bandettini, P. A. (2008). Representational similarity analysis-connecting the branches of systems neuroscience.` [Frontiers in Systems Neuroscience]
* **File & Function**: `src/blme/tasks/geometry/rsa.py` -> `RepresentationalSimilarityTask`
* **Critical Info**: Headline keys: `rsa_adjacent_min_corrdist`, `rsa_early_late_corrdist`. All of them are declared invariant to a global rescale and identity blocks (interior, trailing) (`tests/tasks/invariance/test_rsa.py::test_size_invariant_entry`). RSA is O(N^2) in the number of tokens. Euclidean RDMs and the summaries that average over all layers are `_meta_`. Sink rows (position 0 and tokens whose norm exceeds 10x the median at a middle depth) are excluded at every layer because they occupy the top ranks of every RDM.

## 4. Latent Mahalanobis OOD Distance
* **What are we measuring**: How far Out-Of-Distribution (OOD) a sample is, accounting for the natural covariance of the in-distribution manifold.
* **How are we measuring**: Each text's mean-pooled final-layer state (position 0 and massive-activation rows left out of the mean) is scored by its Mahalanobis distance to a single Gaussian fitted on other texts, with a Ledoit-Wolf covariance. The out-of-distribution set is each held-out text with its tokens shuffled in place (`ood_strategy: shuffle`). `num_samples: 2000` WikiText-103 texts are drawn and about half are held out, with whole articles assigned to one side so that no held-out text shares an article with the fit set; results are averaged over 5 random splits.
* **Hypothesis**: Simple Euclidean distance is flawed in highly anisotropic spaces. Mahalanobis distance correctly scales by the principal axes of variance, providing a true measure of semantic anomaly.
* **Citation/Paper**: `Lee, K., Lee, K., Lee, H., & Shin, J. (2018). A simple unified framework for detecting out-of-distribution samples and adversarial attacks.` [ArXiv: 1807.03888]
* **File & Function**: `src/blme/tasks/geometry/mahalanobis.py` -> `MahalanobisOODTask`
* **Critical Info**: Headline keys: `auroc`, `ood_separation_ratio`, `mahalanobis_sq_per_dim_id`, `mahalanobis_sq_per_dim_ood`, `ood_separation_gap_per_dim`. All of them are declared invariant to zero-padding the width, isometric re-embedding and a global rescale (`tests/tasks/invariance/test_geometry_mahalanobis.py::test_per_dim_forms_invariant`). Raw distances grow with sqrt(d) when the fit set is smaller than the width, so they are reported only as `_meta_`; AUROC, the distance ratio and the squared-distance-per-dimension forms are the comparable outputs. This is the single-Gaussian, mean-pooled form Ren et al. (2022) use for language models; Lee et al.'s class-conditional form needs labels. The task measures how far the representation moves when word order is destroyed at matched vocabulary. Each passage is cut at 128 tokens before the forward pass.

## 5. Representation Sensitivity (`geometry_representation_sensitivity`)
* **What are we measuring**: How sensitive the true-next-token log-probability is to the representation the unembedding reads.
* **How are we measuring**: The mean squared norm of the gradient of the true-next-token log-probability with respect to the final representation, in closed form (the target's unembedding row minus the expected unembedding row), over every prediction position. `S_unit` takes the gradient with respect to the unit-gain normalised state, which absorbs the final-norm gain into the unembedding.
* **Hypothesis**: A larger value means small changes of the final representation move the next-token log-probability more.
* **Citation/Paper**: `Amari, S. (1998). Natural gradient works efficiently in learning.` [Neural Computation, Vol 10(2)] — foundational reference for information geometry of neural networks. Application to LLMs is an active area of research.
* **File & Function**: `src/blme/tasks/geometry/information_geometry.py` -> `RepresentationSensitivityTask`
* **Critical Info**: Headline key: `S_unit`. It is declared invariant to the final-norm/unembedding gauge and a function-preserving residual rescale (`tests/tasks/invariance/test_geometry_representation_sensitivity.py::test_s_unit_invariant_under_final_norm_unembedding_gauge`). This is a BLME construct, not a Fisher-information trace. The raw value depends on how a model splits scale between the final-norm gain and the unembedding, so it is reported only as `_meta_representation_sensitivity_raw`. `S_unit` carries a factor of the width. For a declared final tanh softcap, the derivative of each vocabulary logit enters the score. The reconstructed logits are checked against the model on every document. Defaults: `num_samples: 20`.

## 6. Matrix Entropy (Information Bottleneck)
* **What are we measuring**: The data compression capabilities of the LLM layers over inference.
* **How are we measuring**: The per-sentence von Neumann entropy of the centred, row-normalised token covariance, averaged over sentences; `matrix_entropy` is divided by log d (Wei et al. 2024, Def. 4.1 and 4.3) and `matrix_entropy_raw` is the undivided value. Every token is used and the tokenizer's BOS is kept.
* **Hypothesis**: As information passes through an LLM, the model actively filters out noise. A decreasing or low layer-wise matrix entropy indicates the model is actively forming a tighter semantic "Information Bottleneck".
* **Citation/Paper**: `Wei, L., Tan, Z., Li, C., Wang, J., & Huang, W. (2024). Diff-eRank: A Novel Rank-Based Metric for Evaluating Large Language Models.` [NeurIPS 2024, ArXiv: 2401.17139]
* **Paper summary**: Wei et al. define per-sentence matrix entropy as the von Neumann entropy of the trace-normalized covariance of centered, row-normalized hidden states (Def. 4.1/4.3, averaged over sentences and divided by log d), and show it separates trained from random models and tracks quality; v2 of the paper (Diff-eRank, NeurIPS 2024) recasts the same quantity as an effective-rank difference between the untrained and trained model.
* **File & Function**: `src/blme/tasks/geometry/matrix_entropy.py` -> `MatrixEntropyTask`
* **Critical Info**: Headline keys: `matrix_entropy`, `matrix_entropy_raw`. Declared invariant: `matrix_entropy_raw` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_matrix_entropy.py::test_size_invariant_entry`). Sentences are truncated at 512 tokens (Wei et al. use 2048). Parity with the reference code is checked in `tests/tasks/parity/test_matrix_entropy_parity.py`. Defaults: `num_samples: 10`.

## 7. Correlation Dimension (Fractal Geometry)
* **What are we measuring**: The underlying fractal complexity and self-similarity of the generated language manifold.
* **How are we measuring**: The correlation dimension D2 (Grassberger & Procaccia 1983) is the small-radius slope of log C(r), where C(r) is the fraction of point pairs closer than r. It is computed on one point per sequence: the last token of a 20-word window cut from each passage at a hashed offset (the same words for every model), at the output representation, with Euclidean distance and `num_samples: 1000`. The fit uses Du & Tanaka-Ishii's window, C in [20 / (N(N-1)), 1 / N].
* **Hypothesis**: Correlation dimension can reveal non-integer scaling structure in the sampled representation cloud. It is evidence about fractal-like scaling, not proof that language globally lies on a fractal attractor.
* **Citation/Paper**: `Grassberger, P. & Procaccia, I. (1983). Characterization of strange attractors.` [Phys. Rev. Lett. 50(5)]. LLM precedent for the fit window: Du & Tanaka-Ishii (2024/2025).
* **File & Function**: `src/blme/tasks/geometry/correlation_dimension.py` -> `CorrelationDimensionTask`
* **Critical Info**: Headline key: `correlation_dimension`. It is declared invariant to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_correlation_dimension.py::test_headline_invariant`). D2 at fixed N converges from below, so N is the same for every model. The LLM applications of Du & Tanaka-Ishii measure the trajectory of next-token probability vectors along one long text; BLME measures how the model spreads documents. The mean-pooled document cloud is `_meta_`.
* **Paper summary**: Grassberger & Procaccia define the correlation integral C(r) — the fraction of point pairs within distance r — and show its log-log slope ν (the correlation dimension) measures an attractor's fractal dimensionality from a finite sample; it lower-bounds the Hausdorff dimension and became the standard practical estimator.

## 8. Positional Attention Decay (`geometry_positional_decay`)
* **What are we measuring**: Whether attention falls off with the distance between query and key.
* **How are we measuring**: For every causal query row, the Spearman correlation between key distance and attention probability (negative when nearer keys receive more attention), over the keys before the query with position 0 dropped. Rows are aggregated over heads and layers with weights equal to the norm of each head's write into the residual stream. Every model scores the first 256 content tokens of long WikiText articles; attention is computed in fp32.
* **Hypothesis**: Heads that attend locally give strongly negative rowwise correlations; distance-independent attention gives values near zero.
* **Citation/Paper**: `Su, J., et al. (2021). RoFormer: Enhanced Transformer with Rotary Position Embedding.` and long-context extrapolation methods like `Chen, Q., et al. (2023). Extending Context Window of Large Language Models via Position Interpolation.`
* **File & Function**: `src/blme/tasks/geometry/positional_decay.py` -> `PositionalAttentionDecayTask`
* **Critical Info**: Headline key: `positional_decay_nosink_write_weighted`. It is declared invariant to a function-preserving residual rescale and identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_positional_decay.py::test_weighted_mean_is_invariant_under_identity_blocks`). This is a BLME construct: RoFormer motivates the premise but defines no statistic of trained attention. The rowwise correlation grows in magnitude with row length, which is why the token count is fixed at 256; `documents: dataset` scores the run's passages instead. The value that includes position 0 and the sink mass are `_meta_`. Defaults: `num_samples: 5`.

## 9. SVD Isotropy (geometry_svd)
* **What are we measuring**: The isotropy (roundness) of the representation space.
* **How are we measuring**: One centred cloud pools every token of every document at a layer, with position 0 and massive-norm rows dropped; its spectrum gives the Roy-Vetterli effective rank and the participation ratio. `avg_cosine_similarity` is Ethayarajh's anisotropy baseline: the mean cosine over all distinct pairs of raw (uncentred) states, with every token kept.
* **Hypothesis**: Highly anisotropic spaces (e.g., dominating outlier dimensions) collapse semantics into a narrow cone, degrading similarity metrics. Isotropic spaces utilize capacity more uniformly.
* **Citation/Paper**: `Ethayarajh, K. (2019). How Contextual are Contextualized Word Representations?` [EMNLP 2019, ArXiv: 1909.00512]
* **File & Function**: `src/blme/tasks/geometry/isotropy.py` -> `SVDIsotropyTask`
* **Critical Info**: Headline keys: `avg_cosine_similarity`, `effective_rank`, `participation_ratio`. All of them are declared invariant to zero-padding the width, isometric re-embedding and a global rescale (`tests/tasks/invariance/test_svd.py::test_size_invariant_entry`). The pooled spectra grow with the token count up to min(N - 1, d), so compare models at the same `num_samples`. `cond_number` moves with N and is `_meta_`. Defaults: `num_samples: 100`, `layerwise: false`.
* **Paper summary**: Ethayarajh shows contextual representations are highly anisotropic — random word pairs have near-1 cosine similarity in upper layers of GPT-2/BERT/ELMo — so isotropy-corrected measures are needed; the anisotropy baseline (his Eq. 4) is the expected cosine between uniformly sampled occurrence pairs on raw representations.

## 10. Hubness
* **What are we measuring**: The tendency of certain tokens to be the "nearest neighbor" of an unusually high number of other tokens in latent space.
* **How are we measuring**: On the unembedding rows the tokenizer can emit (a seeded draw of 32000 rows, cosine distance), the k-occurrence distribution N_k counts how often each row appears in other rows' k-nearest-neighbour lists, for each k in `k_values: [10, 50, 100]`. Reported per k: the skewness of N_k (Radovanovic et al.), its maximum, the top-1% mass and the Gini coefficient.
* **Hypothesis**: The "Curse of Dimensionality" leads to spatial hubs in high dimensions. These hubs crowd semantic spaces and degrade zero-shot retrieval and generation.
* **Citation/Paper**: `Radovanovic, M., Nanopoulos, A., & Ivanovic, M. (2010). Hubs in space: Popular nearest neighbors in high-dimensional data.` [JMLR 11:2487-2531]; `Tomašev, Radovanović, Mladenić, Ivanović (2014). The Role of Hubness in Clustering High-Dimensional Data.` [IEEE TKDE 26(3):739-751]
* **Paper summary**: Radovanović et al. show that in high dimensions the k-occurrence distribution becomes heavily right-skewed: a few points ("hubs") appear in a disproportionate share of neighbor lists, an intrinsic-dimensionality effect that degrades nearest-neighbor methods; S_Nk (skewness of N_k) is their canonical hubness measure — exactly what BLME reports. Tomašev et al. extend the analysis to clustering.
* **File & Function**: `src/blme/tasks/geometry/hubness.py` -> `GlobalHubnessTask`
* **Critical Info**: Headline keys: `hubness_k{10,50,100}_skew`, `hubness_k{10,50,100}_max`, `hubness_k{10,50,100}_top1pct`, `hubness_k{10,50,100}_gini`. All of them are declared invariant to zero-padding the width, isometric re-embedding, a global rescale and vocabulary padding (`tests/tasks/invariance/test_geometry_hubness.py::test_width_scale_and_vocabulary_invariant`). The skewness grows with the number of rows, which is why a fixed-size draw is used. The Gini coefficient and top-1% mass are BLME additions. The input-embedding table is reported as `_meta_`.

## 11. Category Separation
* **What are we measuring**: How well conceptually related words group together organically.
* **How are we measuring**: On the input embedding table, per category of single-token words: cosine distances within the category and to 100 random emittable tokens, k-NN purity over the emittable vocabulary (`k_purity: 20`, capped at the category size minus one), hubness inside the category, and, for relation pairs, the consistency of offset vectors.
* **Hypothesis**: A model with a rich geometric understanding of language will organically cluster related concepts (e.g., animals, colors) far from unrelated ones.
* **Citation/Paper**: Derived from general geometric alignment literature [No specific conference paper].
* **File & Function**: `src/blme/tasks/geometry/categories.py` -> `CategoryGeometryTask`
* **Critical Info**: Not cross-model comparable: the word-to-token mapping is tokenizer-specific (only single-token words count), and the task emits `_meta_cross_model_comparable: false`. Headline keys: `{category}_intra`, `{category}_inter`, `{category}_separation`, `{category}_purity`, `{category}_hub_skew`, `{category}_hub_max`, `{relation}_consistency`. Declared invariant: `{category}_intra`, `{category}_inter`, `{category}_separation` to unused zero vocabulary rows (`tests/tasks/invariance/test_categories.py::test_size_invariant_entry`); `{category}_purity`, `{category}_hub_skew`, `{category}_hub_max`, `{relation}_consistency` to unused zero vocabulary rows and unused duplicate vocabulary rows (`tests/tasks/invariance/test_categories.py::test_size_invariant_entry`). Weights only. A 2-D projection is produced when `projection_method` is set.

## 12. Prediction Alignment (`geometry_prediction_alignment`)
* **What are we measuring**: How closely the final hidden state points toward the output-projection vector for the next token.
* **How are we measuring**: The mean per-token difference between cos(h_t, w_(x_(t+1))) and the cosine to the target of another position in the same document (a frequency-preserving derangement), after centring the output-projection rows. Pairs whose source is a sink row are dropped.
* **Hypothesis**: Higher alignment indicates that the representation is geometrically arranged to support the next-token prediction. This is a BLME diagnostic, not a canonical paper metric.
* **Citation/Paper**: Derived from standard output-embedding geometry and logit-lens style analyses; no single canonical paper.
* **File & Function**: `src/blme/tasks/geometry/consistency.py` -> `PredictionAlignmentTask`
* **Critical Info**: Headline keys: `prediction_alignment_mean`, `prediction_alignment_std`. All of them are declared invariant to unused zero vocabulary rows (`tests/tasks/invariance/test_prediction_alignment.py::test_unused_vocabulary_rows_move_nothing`). The matched control cancels anisotropy and token frequency; the raw cosine alone is reproduced by uniformly random rows. Centring and the control use only rows the tokenizer can emit. This is a BLME diagnostic, not a published metric. Defaults: `num_samples: 100`.

## 13. Representation Collapse
* **What are we measuring**: Loss of dimensional spread of the hidden states across depth.
* **How are we measuring**: At each block, the Roy-Vetterli effective rank of one centred cloud pooling every token of every document, with position 0 and massive-norm rows dropped; `collapse_ratio` is min / max over blocks. `qdl_entropy_min` is the compression valley of Queipo-de-Llano et al.: per sequence and without centring, the entropy of s_j^2 / ‖X‖_F^2 with the first-token row kept, computed on the first 64 tokens of every passage that has them, minimised over blocks.
* **Hypothesis**: A low effective rank at some depth indicates that representations concentrate in few directions there.
* **Citation/Paper**: `Dong, Y., Cordonnier, J. B., & Loukas, A. (2021). Attention is Not All You Need: Pure Attention Loses Rank Doubly Exponentially with Depth.` [ICML 2021, ArXiv: 2103.03404]
* **File & Function**: `src/blme/tasks/geometry/collapse.py` -> `RepresentationCollapseTask`
* **Critical Info**: Headline keys: `qdl_entropy_min`, `max_erank`, `min_erank`, `collapse_ratio`. All of them are declared invariant to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, trailing) (`tests/tasks/invariance/test_collapse.py::test_size_invariant_entry`). At the valley the entropy grows with the number of rows, which is why `qdl_entropy_min` uses a fixed 64 tokens; the whole-passage value is `_meta_`. `max_drop` and the per-layer lists depend on how the network is split into blocks and are `_meta_`. The pooled effective rank grows with the token count, so compare models at the same `num_samples`.

## 14. Weight Spectral Decay
* **What are we measuring**: Heavy-tailed spectral structure and effective utilization of learned weight matrices.
* **How are we measuring**: Scanning linear/Conv1D weight matrices: every block's attention and MLP matrices plus the LM head, without position embeddings (WeightWatcher's default module set differs: gpt2 `avg_alpha_official` 3.9045 here vs 3.8647). `alpha_official` is the HT-SR estimator: the Clauset power-law MLE alpha = 1 + n / sum ln(lambda / x_min) with a KS-optimal x_min scan on the correlation-matrix eigenvalues; `alpha_hat` = alpha x log10(lambda_max) (Martin & Mahoney); the stable rank is ‖W‖_F^2 / ‖W‖_2^2 (Rudelson & Vershynin 2007).
* **Hypothesis**: Heavy-tailed spectra can indicate learned correlation structure and implicit self-regularization; extreme collapse or noise-like spectra are warnings.
* **Citation/Paper**: `Martin, C. H. & Mahoney, M. W. (2019/2021). Traditional and Heavy-Tailed Self Regularization in Neural Network Models / Heavy-Tailed Universality Predicts Trends in Test Accuracies.`
* **Paper summary**: Martin & Mahoney's Heavy-Tailed Self-Regularization theory fits power laws to the eigenvalue spectral density of weight matrices and finds that well-trained networks develop heavy tails (small α) without explicit regularization; across families, smaller/more uniform α predicts better test accuracy — with the follow-up (Martin, Peng & Mahoney, Nat. Comms. 2021) showing α-based metrics predict quality WITHOUT any training/test data. BLME reports the eigenvalue power-law fit as `alpha_official` and keeps a fixed-tail Hill estimate as `_meta_avg_alpha`.
* **File & Function**: `src/blme/tasks/geometry/spectral.py` -> `WeightSpectralTask`
* **Critical Info**: Headline keys: `avg_alpha_official`, `median_alpha_official`, `avg_alpha_hat`, `avg_stable_rank`. All of them are declared invariant to zero-padding the width (`tests/tasks/invariance/test_spectral.py::test_size_invariant_entry`). Weights only. A fixed-tail Hill estimate (`tail_fraction: 0.2`) is reported as `_meta_avg_alpha`.

## 15. HSIC Dependence (`geometry_hsic`)
* **What are we measuring**: Kernel dependence between the token clouds of different layers.
* **How are we measuring**: Hilbert-Schmidt Independence Criterion between the centred Gram matrices of layers' token clouds (sink rows excluded, at most `max_hsic_tokens: 2000` tokens). The headlines are normalised HSIC, HSIC(K, L) / √(HSIC(K, K)·HSIC(L, L)), which with linear kernels is linear CKA on a seeded 2000-token subsample: the minimum over adjacent layers, and `hsic_compression_ratio`, which despite its name is that normalised dependence between the first and last layer, not a ratio. Each has a debiased twin.
* **Hypothesis**: High HSIC indicates strong statistical dependence between two representation views; low HSIC suggests a stronger transformation or decorrelation.
* **Citation/Paper**: `Gretton, A., Bousquet, O., Smola, A., & Schölkopf, B. (2005). Measuring Statistical Dependence with Hilbert-Schmidt Norms.` Related representation-similarity use in `Kornblith et al. (2019). Similarity of Neural Network Representations Revisited.`
* **File & Function**: `src/blme/tasks/geometry/mutual_info.py` -> `HSICDependenceTask`
* **Critical Info**: Headline keys: `min_adjacent_hsic`, `hsic_compression_ratio`, `min_adjacent_hsic_debiased`, `hsic_compression_ratio_debiased`. Declared invariant: `min_adjacent_hsic`, `hsic_compression_ratio` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, trailing) (`tests/tasks/invariance/test_hsic.py::test_size_invariant_entry`); `min_adjacent_hsic_debiased`, `hsic_compression_ratio_debiased` to the sample count N, zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, trailing) (`tests/tasks/invariance/test_hsic.py::test_size_invariant_entry`). Registered task name is `geometry_hsic`; there is no `geometry_mutual_info` task. HSIC measures dependence and is not a mutual-information estimate.

## 16. CKA (Centered Kernel Alignment)
* **What are we measuring**: The similarity between the underlying structures of two sets of representations without requiring them to have the same features.
* **How are we measuring**: Linear CKA (Kornblith et al., Eq. 3-4) between layers' token clouds, sink rows excluded, with a debiased twin based on the unbiased HSIC U-statistic. The headlines are the first-last value, the minimum over all layer pairs and the minimum over adjacent layers.
* **Hypothesis**: Permits diagnosing whether two distinct layers (or models) are learning structurally analogous concepts, ignoring rotations or isotropic scalings. 
* **Citation/Paper**: `Kornblith, S., Norouzi, M., Lee, H., & Hinton, G. (2019). Similarity of neural network representations revisited.` [ICML 2019, ArXiv: 1905.00414]
* **File & Function**: `src/blme/tasks/geometry/cka.py` -> `CKATask`
* **Critical Info**: Headline keys: `early_late_cka`, `min_offdiag_cka`, `min_adjacent_cka`, `early_late_cka_debiased`, `min_offdiag_cka_debiased`, `min_adjacent_cka_debiased`. Declared invariant: `early_late_cka`, `min_offdiag_cka`, `min_adjacent_cka` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, trailing) (`tests/tasks/invariance/test_cka.py::test_size_invariant_entry`); `early_late_cka_debiased`, `min_offdiag_cka_debiased`, `min_adjacent_cka_debiased` to the sample count N, zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, trailing) (`tests/tasks/invariance/test_cka.py::test_size_invariant_entry`). Defaults: `num_samples: 100`.

## 17. Unembedding Geometry
* **What are we measuring**: Static geometry of the LM head (unembedding) matrix: how many directions it effectively uses, whether semantically related tokens cluster, and how it relates to the input embeddings.
* **How are we measuring**: Static diagnostics of the unembedding matrix: the Roy-Vetterli effective rank of its raw rows and of the mean-centred rows, read only on the rows the tokenizer can emit; a category-purity score over a bundled concept taxonomy (`k: 20`); and the cosine between each row and its final-normed input embedding.
* **Hypothesis**: Higher effective rank = richer prediction geometry; higher purity = semantically organized unembedding space; alignment characterizes how far apart the input/output vocabularies drift in untied models.
* **Citation/Paper**: Effective rank: `Roy, O. & Vetterli, M. (2007). The Effective Rank: A Measure of Effective Dimensionality.` [EUSIPCO 2007]. The purity and alignment summaries are BLME diagnostics.
* **Paper summary**: Roy & Vetterli define the effective rank as exp of the Shannon entropy of the L1-normalized singular values — a smooth, threshold-free count of "how many dimensions the matrix really uses"; BLME applies it to the raw unembedding rows and, as a separate key, to the mean-centred rows.
* **File & Function**: `src/blme/tasks/geometry/unembedding.py` -> `UnembeddingDiagnosticsTask`
* **Critical Info**: Headline keys: `unembedding_eff_rank`, `unembedding_eff_rank_centered`. All of them are declared invariant to zero-padding the width and vocabulary padding (`tests/tasks/invariance/test_unembedding.py::test_size_invariant_entry`). Weights only. Purity depends on which words the tokenizer maps to single tokens and is a within-tokenizer `_meta_` diagnostic. The alignment keys are `_meta_`: on a tied model they compare a row with its own final-normed copy. The all-rows effective ranks are also kept as `_meta_`.

## 18. Perplexity (Baseline / Y-variable Geometry)
* **What are we measuring**: Baseline auto-regressive predictability.
* **How are we measuring**: The joined passages are scored as one stream with a 1024-token window and stride 512. `bits_per_byte` divides total negative log likelihood in bits by the UTF-8 bytes attributable to the scored targets. When the sole unscored token is an inserted BOS and the scored suffix decodes exactly to the source, all source bytes count. Ambiguous attribution leaves the headline unavailable and reports a lower bound. The task also reports `ppl_overall` and rare/frequent-token diagnostics.
* **Hypothesis**: As the foundational sanity check, it proves the model can actually model text. Used purely as a baseline correlate for other intrinsic measures.
* **Citation/Paper**: Canonical language modeling metric. 
* **File & Function**: `src/blme/tasks/geometry/perplexity.py` -> `RarePPLTask`
* **Critical Info**: Headline key: `bits_per_byte`. It is declared invariant to vocabulary padding (`tests/tasks/invariance/test_geometry_perplexity.py::test_bits_per_byte_invariant_under_masked_vocabulary_padding`). Lower is better. This is a performance-like baseline, not an intrinsic predictor. Bits per byte removes the tokenizer's per-token units; perplexity does not. Defaults: `num_samples: 100`.

## 19. Global Intrinsic Dimension (geometry_intrinsic_dim / PDE)
* **What are we measuring**: The global effective dimensionality of the dataset within the model's space.
* **How are we measuring**: TwoNN (Facco et al. 2017): the ratio of each point's second- to first-nearest-neighbour distance, fitted through the origin with the top 10% of ratios discarded. The default static mode (`layerwise: false`) measures the input-embedding rows. In layerwise mode it is applied at every block output to one point per sequence: the last token of a 20-word window cut from each passage at a hashed offset (the same words for every model), with `num_samples: 1000` and Euclidean distance.
* **Hypothesis**: Models that operate heavily on distinct subspaces lower the overall effective dimension. A model perfectly memorizing data tends to have very sparse high dimensions.
* **Citation/Paper**: `Facco, E., d'Errico, M., Rodriguez, A., & Laio, A. (2017). Estimating the intrinsic dimension of datasets by a minimal neighborhood information.` [Scientific Reports]
* **File & Function**: `src/blme/tasks/geometry/intrinsic_dim.py` -> `IntrinsicDimensionTask`
* **Critical Info**: Headline keys (`layerwise: true`): `lid_first_layer`, `lid_mid_layer`, `lid_last_layer`. Layerwise mode is the default; static mode (`layerwise: false`) emits only `intrinsic_dimension`, a vocabulary-dependent key that is not a headline. Declared invariant: `lid_first_layer` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, trailing) (`tests/tasks/invariance/test_geometry_intrinsic_dim.py::test_endpoints_invariant`); `lid_last_layer` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_intrinsic_dim.py::test_endpoints_invariant`). TwoNN falls as N grows, so the layerwise value is the dimension at a fixed 1000-point scale. A token cloud pooled across documents is avoided because many of a token's nearest neighbours lie in its own document; its value is kept as `_meta_tokens_*`. Returns global scalars, in contrast to `geometry_lid`, which averages local estimates.
* **Paper summary**: Facco et al.'s Two-NN estimates global intrinsic dimension from only the two nearest neighbors of each point: the ratio μ = r2/r1 follows a Pareto distribution with exponent d, so a straight-line fit through the origin of the empirical CDF recovers d — minimizing the effect of density variation and curvature; they discard the top 10% of μ values for robustness (BLME matches, tail_trim=0.1).

## 20. Trajectory Curvature (geometry_trajectory_curvature)
* **What are we measuring**: How straight the token-position trajectory of a sentence is at each layer, and how much deeper layers *straighten* it.
* **How are we measuring**: For per-sample hidden states $x_1 \dots x_T$ at a layer, form difference vectors $v_t = x_{t+1} - x_t$ and compute the discrete curvature $c_t = \arccos\!\big(\langle v_t, v_{t+1}\rangle / (\lVert v_t\rVert\,\lVert v_{t+1}\rVert)\big)$ at each interior position; the per-layer curvature is the mean over positions and samples (radians). `straightening_ratio` $= (c_\text{first} - c_\text{last})/c_\text{first}$, where the first layer is the output of the first block.
* **Hypothesis**: Trained LMs progressively straighten sentence trajectories with depth — straighter paths permit prediction by linear extrapolation — and models with better next-word prediction straighten more. A positive `straightening_ratio` / negative `curvature_slope` is the expected signature of a well-trained model.
* **Citation/Paper**: `Hosseini, E. A. & Fedorenko, E. (2023). Large language models implicitly learn to straighten neural sentence trajectories to construct a predictive representation of natural language.` [NeurIPS 2023, ArXiv: 2311.04930]
* **File & Function**: `src/blme/tasks/geometry/trajectory_curvature.py` -> `TrajectoryCurvatureTask`
* **Critical Info**: Headline keys: `straightening_ratio`, `curvature_mean_first_layer`, `curvature_mean_last_layer`. Declared invariant: `straightening_ratio`, `curvature_mean_first_layer` to isometric re-embedding, zero-padding the width, a global rescale and identity blocks (interior, trailing) (`tests/tasks/invariance/test_geometry_trajectory_curvature.py::test_endpoints_invariant_under_identity_blocks`); `curvature_mean_last_layer` to isometric re-embedding, zero-padding the width, a global rescale and identity blocks (interior, trailing, leading) (`tests/tasks/invariance/test_geometry_trajectory_curvature.py::test_endpoints_invariant_under_identity_blocks`). Trajectory order matters: the task reads per-sample `(T, D)` chunks, never the flattened token cloud. A tokenizer-added BOS row is skipped (`skip_first_tokens: auto`); cosines are clamped to $[-1, 1]$ and zero-norm difference vectors are skipped. Position 0 is dropped only when the tokenizer prepends a BOS (`skip_first_tokens: auto`); on BOS-less tokenizers such as gpt2's it is kept (dropping it moves gpt2's ratio by −0.8%).
* **Paper summary**: Hosseini & Fedorenko show that trained LMs "straighten" sentence trajectories with depth — the discrete curvature (angle between consecutive difference vectors of the hidden-state trajectory) decreases relative to the first contextualized layer — and that models with better next-word prediction straighten more; curvature is averaged per sentence, then across sentences.

## 21. Marchenko-Pastur Bulk Deviation (geometry_mp_bulk_deviation)
* **What are we measuring**: How strongly per-layer activation spectra deviate from the random-matrix-theory iid null, i.e. how much *structure* (spiked directions) the representation carries beyond noise.
* **How are we measuring**: At the first, middle and last layers, each dimension of the pooled token cloud (position 0 and massive-norm rows dropped) is z-scored and the eigenvalues of the correlation matrix are compared with the Marchenko-Pastur law of ratio $\gamma = D/N$. Reported: the fraction of eigenvalues above the buffered upper edge (`mp_outlier_frac`, `edge_tol: 0.05`), the variance fraction they carry (`mp_spike_energy`), and the KS distance to the MP CDF (`mp_ks_distance`). The headline `*_g25` family evaluates these on a seeded subsample of N = 4D + 1 tokens, so that $\gamma$ = 0.25 for every model. Lower-edge statistics (`lower_outlier_frac`, `lower_energy`; Staats et al. 2024, arXiv:2410.17770) count eigenvalues below the bulk and are NaN for $\gamma \ge 1$.
* **Hypothesis**: Real activations are highly structured: a substantial outlier fraction and spike energy indicate many learned signal directions standing above the noise bulk (BBP-supercritical spikes). Models whose spectra hug the MP bulk encode little linear structure at that layer.
* **Citation/Paper**: `Marchenko, V. A. & Pastur, L. A. (1967). Distribution of eigenvalues for some sets of random matrices.` [Mat. Sb. 72(114):4; Math. USSR-Sbornik 1(4), 457-483] and `Baik, J., Ben Arous, G., & Péché, S. (2005). Phase transition of the largest eigenvalue for nonnull complex sample covariance matrices.` [Annals of Probability 33(5), 1643-1697, ArXiv: math/0403022]
* **Paper summary**: Marchenko & Pastur derive the limiting eigenvalue distribution of sample covariance matrices of iid noise — the "MP bulk" with support [(1±√γ)²] and, for γ>1, a point mass at 0 from rank deficiency. Baik, Ben Arous & Péché characterize when a true signal direction escapes the bulk (the BBP phase transition): spikes above the threshold detach as outlier eigenvalues. BLME uses both as the null model: eigenvalues above the buffered bulk edge are learned structure, and the KS distance to the γ-matched MP CDF summarizes overall deviation from noise.
* **File & Function**: `src/blme/tasks/geometry/rmt_bulk.py` -> `MPBulkDeviationTask`
* **Critical Info**: Headline keys: `mp_outlier_frac_g25_first`, `mp_outlier_frac_g25_mid`, `mp_outlier_frac_g25_last`, `mp_outlier_frac_g25_mean`, `mp_spike_energy_g25_first`, `mp_spike_energy_g25_mid`, `mp_spike_energy_g25_last`, `mp_spike_energy_g25_mean`, `mp_ks_distance_g25_first`, `mp_ks_distance_g25_mid`, `mp_ks_distance_g25_last`, `mp_ks_distance_g25_mean`. All of them are declared invariant to zero-padding the width and a global rescale (`tests/tasks/invariance/test_mp_bulk_deviation.py::test_size_invariant_entry`). The number of spikes that clear the edge grows with N / D, which is why the fixed-$\gamma$ family is the headline and the $\gamma$-matched family is `_meta_`. Tokens from one document are correlated, which the iid null ignores. Per-coordinate z-scoring presumes a privileged basis, so an isometric re-embedding moves every key. Defaults: `num_samples: 400`, `layers: first_mid_last`, `max_tokens: 20000`, `edge_tol: 0.05`, `fixed_gamma: 0.25`.

* **How are we measuring**: Computing Ethayarajh-style self-similarity, intra-sentence similarity, and maximum explainable variance summaries over hidden states.
* **Hypothesis**: Stronger contextualization means token representations depend meaningfully on context rather than collapsing to static lexical identity.
* **Citation/Paper**: `Ethayarajh, K. (2019). How Contextual are Contextualized Word Representations?` [EMNLP 2019, ArXiv: 1909.00512]

## 23. IsoScore
* **What are we measuring**: Uniformity of embedding-space dimension utilization.
* **How are we measuring**: Rudman et al.'s covariance-isotropy IsoScore on the cloud of every token (position 0 included) of `num_samples: 1000` documents.
* **Hypothesis**: More isotropic representations use dimensional capacity more evenly and avoid narrow anisotropy cones.
* **Citation/Paper**: `Rudman, W., Gillman, N., Rayne, T., & Eickhoff, C. (2022). IsoScore: Measuring the Uniformity of Embedding Space Utilization.` [Findings of ACL 2022, ArXiv: 2108.07344]
* **File & Function**: `src/blme/tasks/geometry/isotropy.py` -> `IsoScoreTask`
* **Critical Info**: Headline keys: `isoscore`, `isoscore_effective_dims`. Declared invariant: `isoscore_effective_dims` to zero-padding the width, isometric re-embedding and a global rescale (`tests/tasks/invariance/test_isoscore.py::test_size_invariant_entry`). `isoscore_effective_dims` = IsoScore x (d - 1) + 1 is the participation ratio of the covariance spectrum. Rudman et al. require many more points than dimensions: the realised ratio is reported as `_meta_points_per_dim` and compared with `min_points_per_dim: 50` in `_meta_sampling_regime_ok`; the score is not gated on it, and N <= d is flagged by `_meta_isoscore_rank_deficient`. The value without position 0 is `_meta_isoscore_excl_pos0`. Distinct from `geometry_svd`, which reports effective-rank diagnostics.
* **Paper summary**: Rudman et al.'s IsoScore measures what fraction of dimensions a point cloud uses uniformly: PCA-align, L2-normalize the covariance spectrum, measure its distance from the identity, and rescale so an isotropic cloud scores 1 and a 1-dimensional cloud scores ~0 (Algorithm 1 / Eq. 4.1); unlike partition-function isotropy measures it is rotation-invariant and has an exact k-of-n interpretation.

## 24. Neural Collapse
* **What are we measuring**: Next-token neural collapse: how tightly the final hidden states of positions that share a next token cluster, relative to the distances between class means.
* **How are we measuring**: Following Wu & Papyan (2024), every corpus position t < T - 1 is a sample whose feature is the post-final-norm hidden state and whose class is the next token (position 0 included). Their class-distance normalised variance (Eq. 4) scales as 1/c² with the feature scale and is `_meta_nc1_cdnv`; the headline `nc1_cdnv_galanti` is Galanti's scale-free form. Classes need at least `min_per_class: 10` samples; the corpus is the run's documents (`num_samples: 1000`).
* **Hypothesis**: Lower within-class variability relative to between-class distance indicates a more collapsed next-token representation geometry.
* **Citation/Paper**: `Papyan, V., Han, X. Y., & Donoho, D. L. (2020). Prevalence of neural collapse during the terminal phase of deep learning training.` [PNAS, ArXiv: 2008.08186]
* **File & Function**: `src/blme/tasks/geometry/neural_collapse.py` -> `NeuralCollapseTask`
* **Critical Info**: Headline key: `nc1_cdnv_galanti`. Declared invariant: `nc1_cdnv_galanti` to a scalar final-norm gauge (`tests/tasks/invariance/test_neural_collapse.py::test_galanti_twin_is_free_of_the_feature_scale`). The paper trains on TinyStories and leaves the class-size threshold open; BLME uses the run's corpus. A topic-label variant on mean-pooled sentences is kept as `_meta_topic_*`.

## 25. Schatten / MNN / RankMe
* **What are we measuring**: Spectral summaries of per-text hidden-state matrices.
* **How are we measuring**: Every model scores the first `seq_tokens: 256` tokens (tokenizer defaults) of long WikiText articles, capped at the model's context. `schatten_1` and `schatten_4` are the raw Schatten norms of the MLP-internal activation (the down-projection's input), averaged over layers and then texts (Yusupov et al.). The Matrix Nuclear-Norm follows the released `MNN.py` on the last hidden state, divided by the token count. RankMe is applied per text to the last-layer matrix.
* **Hypothesis**: Spectral concentration and nuclear-norm summaries can proxy representation compression and rank utilization.
* **Citation/Paper**: `Yusupov et al. (2025). From Internal Representations to Text Quality: A Geometric Approach to LLM Evaluation.` [ArXiv: 2509.25359]; `Li, Xia, Chang, & Wu (2024). Large Language Model Evaluation via Matrix Nuclear-Norm.` [ArXiv: 2410.10672]; `Garrido et al. (2023). RankMe.` [ICML 2023, ArXiv: 2210.02885]
* **Paper summary**: Li et al. propose the Matrix Nuclear-Norm — an O(n²) L1,2 column-norm upper bound on the nuclear norm of the (centered, row-normalized) hidden-state matrix — as a single capability/compression scalar that avoids O(n³) SVDs. Yusupov et al. stress-test Schatten norms and related rank/geometry metrics of internal representations as reference-free text-quality signals (noting Schatten norms partly track output length — one reason BLME scores a fixed number of tokens per text). Garrido et al.'s RankMe (exp of the entropy of normalized singular values) predicts downstream quality of self-supervised representations without labels.
* **File & Function**: `src/blme/tasks/geometry/schatten.py` -> `SchattenNormTask`
* **Critical Info**: Headline keys: `schatten_1`, `schatten_4`, `rankme_last`, `row_normalized_rankme_last`, `row_normalized_matrix_nuclear_norm_last`, `row_normalized_schatten_inf_last`. No key is declared size-invariant. Every key grows with the token count, which is why the token count is fixed. `schatten_2` is not reported after row-L2 normalisation because it is a function of token count and width only. Defaults: `num_samples: 10`, `documents: long`, `seq_tokens: 256`.

## 27. Weight Norm Profiles
* **What are we measuring**: Layerwise norms and stable-rank style summaries of model weight matrices.
* **How are we measuring**: Each transformer block's weight matrices are summarised by their Frobenius norm, largest singular value and stable rank, averaged within the block and then over blocks. `norm_uniformity` = max(0, 1 - CV) of the per-block Frobenius norms.
* **Hypothesis**: Extreme layer-norm concentration can reveal architectural or training instabilities.
* **Citation/Paper**: Standard definitions — Frobenius norm, spectral norm (σ_max), stable rank ‖W‖_F²/‖W‖_2² (Rudelson & Vershynin 2007).

## 28. Metric-Space Magnitude (geometry_magnitude)
* **What are we measuring**: The "effective number of distinct points" of a representation cloud across geometric scales — a diversity/structure summary from category theory.
* **How are we measuring**: Magnitude |tX| = 1ᵀ ζ⁻¹ 1 with ζ_ij = exp(-t d_ij), evaluated, as magnipy does by default, at 30 evenly spaced scales on [0, t_conv] with cosine distance 1 − cos(x_i, x_j) (`n_scales: 10` sets only the geometric ladder of the Euclidean `_meta_` summary), on one point per sequence: the last token of a 20-word window cut from each passage at a hashed offset (the same words for every model), at the last layer, with `num_samples: 1000`. `magnitude_area_tconv` is the area under the magnitude function over [0, t_conv] divided by t_conv, where t_conv is the scale at which the magnitude reaches 95% of the number of points; `magnitude_dimension_tconv` is the maximum slope of the log-log magnitude function on that range.
* **Hypothesis**: Magnitude profiles capture multi-scale diversity: higher magnitude at moderate scales = more effectively distinct representations; the magnitude dimension proxies intrinsic dimensionality.
* **Citation/Paper**: `Limbeck, K., Andreeva, R., Sarkar, R., & Rieck, B. (2024). Metric Space Magnitude for Evaluating the Diversity of Latent Representations.` [NeurIPS 2024, ArXiv: 2311.16054]
* **Paper summary**: Limbeck et al. bring Leinster's metric-space magnitude to representation learning: magnitude counts the effective number of distinct points as a function of scale, and its area/dimension summaries quantify diversity robustly. They propose magnitude-based diversity measures for embeddings and validate against known diversity manipulations. BLME reads the area and the dimension over [0, t_conv], the paper's convergence scale.
* **File & Function**: `src/blme/tasks/geometry/magnitude.py` -> `MagnitudeTask`
* **Critical Info**: Headline keys: `magnitude_area_tconv`, `magnitude_dimension_tconv`. All of them are declared invariant to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_magnitude.py::test_headline_invariant`). One O(n³) solve per scale. Duplicate points make ζ singular; a perturbation fallback matching magnipy is used. The raw area is `_meta_`.

## 29. Vendi Score (geometry_vendi_score)
* **What are we measuring**: The effective number of distinct samples in a representation cloud — exp of the Shannon entropy of the similarity-kernel eigenvalues.
* **How are we measuring**: VS = exp(-Σ λ_i log λ_i) for the eigenvalues of K / n, with K the cosine kernel (`kernel: cosine`), on one point per sequence: the last token of a 20-word window cut from each passage at a hashed offset (the same words for every model), at every block output, with `num_samples: 1000`.
* **Hypothesis**: Higher Vendi score = more diverse representations; with the default cosine kernel it is the exponential of a matrix entropy over one vector per sequence.
* **Citation/Paper**: `Friedman, D. & Dieng, A. B. (2023). The Vendi Score: A Diversity Evaluation Metric for Machine Learning.` [TMLR 2023, ArXiv: 2210.02410]
* **Paper summary**: Friedman & Dieng define the Vendi Score as the exponential of the von Neumann entropy of a similarity kernel — a reference-free diversity metric requiring no labels or reference distribution, interpretable as the effective number of dissimilar samples. They apply it across modalities to diagnose mode collapse and diversity trade-offs.
* **File & Function**: `src/blme/tasks/geometry/vendi.py` -> `VendiScoreTask`
* **Critical Info**: Headline keys: `vendi_mean_first_layer`, `vendi_mean_mid_layer`, `vendi_mean_last_layer`, `vendi_max`. Declared invariant: `vendi_mean_first_layer`, `vendi_max` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, trailing) (`tests/tasks/invariance/test_geometry_vendi_score.py::test_endpoints_and_max_invariant`); `vendi_mean_last_layer` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_vendi_score.py::test_endpoints_and_max_invariant`). ## 30. Persistent-Homology Dimension (geometry_phd_dimension)
* **What are we measuring**: A topologically-motivated intrinsic dimension: how total minimum-spanning-tree edge length scales with sample size.
* **How are we measuring**: The GPTID estimator, per text: for subsample sizes n, the total H0 persistence (minimum-spanning-tree length) E(n) scales as n^((d-1)/d); d is recovered from the log-log slope m as d = 1 / (1 - m), with medians over subsamples and averaged restarts. Texts are whole WikiText-103 articles of at least 512 words (`min_doc_words: 512`, selected by word count so every tokenizer gets the same articles; `num_samples: 100`); each text's cloud is its tokens [1:-1], up to `max_length: 512`. `phd_dimension` is the mean over texts and `phd_dimension_std` their standard deviation.
* **Hypothesis**: Lower PHD = more compressed, lower-dimensional representation manifolds; Tulchinskii et al. show PHD separates human from AI-generated text.
* **Citation/Paper**: `Tulchinskii, E., Kuznetsov, K., Kushnareva, L., Cherniavskii, D., Nikolenko, S., Burnaev, E., Barannikov, S., & Piontkovskaya, I. (2023). Intrinsic Dimension Estimation for Robust Detection of AI-Generated Texts.` [NeurIPS 2023, ArXiv: 2306.04723]
* **Paper summary**: The paper shows text embeddings of human-written text have a characteristically higher persistent-homology dimension (~9 for human vs ~7 for generated English), giving a robust AI-text detector that survives domain shift. The PHD estimator itself (MST-length power law) goes back to Birdal et al.'s topological generalization bounds; Tulchinskii et al.'s GPTID implementation is the official reference.
* **File & Function**: `src/blme/tasks/geometry/phd_dimension.py` -> `PHDimensionTask`
* **Critical Info**: Headline keys: `phd_dimension`, `phd_dimension_std`. All of them are declared invariant to zero-padding the width, isometric re-embedding and a global rescale (`tests/tasks/invariance/test_geometry_phd_dimension.py::test_per_text_phd_invariant`). A stochastic estimator with a fixed seed (`seed: 42`). GPTID returns 1 / (1 - m) regardless of alpha, which is the correct inversion only at `alpha: 1.0`.

## 31. CKNNA — Mutual-kNN Conditional CKA (geometry_cknna)
* **What are we measuring**: LOCAL representational alignment between layers: CKA restricted to pairs that are mutual k-nearest neighbors, so only local-neighborhood structure contributes.
* **How are we measuring**: Points are texts: each layer of each text is its masked token mean (position 0 included; `num_samples: 1024`). Features are row-L2-normalised and CKNNA = HSIC(mask⊙K, mask⊙L) / (√(HSIC(mask_K⊙K, ·) · HSIC(mask_L⊙L, ·)) + 1e-6) with the mutual-kNN mask (`topk: 10`) and the unbiased HSIC (Song et al. 2012, Eq. 5). As in platonic-rep, features are first clamped at one global 0.95 quantile of their absolute values (outlier removal) and the kernel runs in float32.
* **Hypothesis**: Per the Platonic Representation Hypothesis, alignment between representations (especially local-neighborhood alignment) increases with model capability and across modalities.
* **Citation/Paper**: `Huh, M., Cheung, B., Wang, T., & Isola, P. (2024). Position: The Platonic Representation Hypothesis.` [ICML 2024, PMLR 235:20617-20642, ArXiv: 2405.07987]
* **Paper summary**: Huh et al. argue that as models scale, their representations converge toward a shared statistical model of reality across architectures and modalities; they measure this convergence with mutual-kNN alignment metrics (CKNNA is their kernel-alignment variant defined in the appendix) and show alignment increases with scale and downstream competence.
* **File & Function**: `src/blme/tasks/geometry/cknna.py` -> `CKNNATask`
* **Critical Info**: Headline keys: `avg_adjacent_cknna`, `min_adjacent_cknna`, `max_adjacent_cknna`, `std_adjacent_cknna`, `mean_offdiag_cknna`, `std_offdiag_cknna`, `min_offdiag_cknna`, `early_late_cknna`, `first_middle_cknna`. No key is declared size-invariant. Identical inputs give about 1.0 (exactly 1.0 only with the biased HSIC, because of the +1e-6 regulariser). `distance_agnostic=True` raises `NotImplementedError`.

## 32. Procrustes Linearity (geometry_procrustes_linearity)
* **What are we measuring**: How close each adjacent-layer transformation is to a LINEAR map — the "transformers are secretly linear" signature.
* **How are we measuring**: Per adjacent layer pair, both clouds are centred and Frobenius-normalised, the unconstrained least-squares map A = X⁺Y is fitted (this is not orthogonal Procrustes), and the similarity 1 - ‖XA - Y‖_F² is reported, following the LLM-Microscope procedure. The rows exclude position 0 and the massive-activation rows (`TOKEN_POLICY = "exclude_sinks"`), with one mask per token taken from the middle block outputs and shared by every layer: on gpt2 position 0 holds about 94% of the centred sum of squares (`_meta_position0_share`), so a fit on every position mostly scores the sink. The released notebook's every-position values are `_meta_incl_pos0_*`. Summaries over depth and an adjusted family are reported.
* **Hypothesis**: Adjacent-layer maps in trained LMs are nearly linear (similarity ≈ 0.99); departures localize where nonlinear computation concentrates.
* **Citation/Paper**: `Razzhigaev, A., Mikhalchuk, M., Goncharova, E., Gerasimenko, N., Oseledets, I., Dimitrov, D., & Kuznetsov, A. (2024). Your Transformer is Secretly Linear.` [ACL 2024 (long), ArXiv: 2405.12250]
* **Paper summary**: The paper finds a near-perfect linear relationship (Procrustes similarity ~0.99) between sequential transformer layers' embeddings, shows the linearity is connected to the residual stream's dominance, and demonstrates that pruning the most-linear layers (or regularizing linearity away) barely hurts — evidence that much of depth is close to linear.
* **File & Function**: `src/blme/tasks/geometry/procrustes_linearity.py` -> `ProcrustesLinearityTask`
* **Critical Info**: Headline keys: `procrustes_linearity_mean`, `procrustes_linearity_min`, `procrustes_linearity_max`, `procrustes_linearity_first`, `procrustes_linearity_last`, `procrustes_linearity_slope`, `procrustes_linearity_q25`, `procrustes_linearity_q50`, `procrustes_linearity_q75`, `procrustes_linearity_adjusted_mean`, `procrustes_linearity_adjusted_min`, `procrustes_linearity_adjusted_max`, `procrustes_linearity_adjusted_first`, `procrustes_linearity_adjusted_last`, `procrustes_linearity_adjusted_q25`, `procrustes_linearity_adjusted_q50`, `procrustes_linearity_adjusted_q75`. Declared invariant: `procrustes_linearity_min` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_procrustes_linearity.py::test_size_invariant_entry`); `procrustes_linearity_first` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, trailing) (`tests/tasks/invariance/test_procrustes_linearity.py::test_size_invariant_entry`); `procrustes_linearity_last` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, leading) (`tests/tasks/invariance/test_procrustes_linearity.py::test_size_invariant_entry`); `procrustes_linearity_adjusted_min` to the sample count N, zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_procrustes_linearity.py::test_size_invariant_entry`); `procrustes_linearity_adjusted_first` to the sample count N, zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, trailing) (`tests/tasks/invariance/test_procrustes_linearity.py::test_size_invariant_entry`); `procrustes_linearity_adjusted_last` to the sample count N, zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, leading) (`tests/tasks/invariance/test_procrustes_linearity.py::test_size_invariant_entry`); `procrustes_linearity_adjusted_mean`, `procrustes_linearity_adjusted_max`, `procrustes_linearity_adjusted_q25`, `procrustes_linearity_adjusted_q50`, `procrustes_linearity_adjusted_q75` to the sample count N, zero-padding the width, isometric re-embedding and a global rescale (`tests/tasks/invariance/test_procrustes_linearity.py::test_size_invariant_entry`). The absolute value depends on the conditioning of X; read the profile across depth. Defaults: `num_samples: 100`. The chain ends at the raw last-block output, before the final norm (the release notebook stops one block earlier). `procrustes_linearity_slope` is the OLS slope over normalised depth (per unit of depth fraction).

**Document-held-out linearity.** `procrustes_linearity_heldout_r2_mean` measures how well an adjacent-layer affine map predicts token representations in unseen documents. BLME groups the default WikiText passages by article before splitting. For a custom corpus, supply a string or integer `document_id`, `doc_id` or `article_id` on every chunk of a document. Python integers and signed or unsigned NumPy integers with the same value identify the same document. A record without a parent ID constitutes one document. When requesting WikiText passages directly, use `load_default_corpus(n, include_document_ids=True)` to retain the article identifiers.

Every fifth sorted eligible document ID enters the outer test set, starting with the first. Inside the remaining documents, every fifth ID serves as validation for choosing a cutoff for each layer pair. The inner fit learns its own sink thresholds, means and float64 SVD. It tests relative cutoffs of `sqrt(eps_float32)` (0.000345267), 0.001, 0.0031623, 0.01, 0.031623 and 0.1. The smallest cutoff tied for minimum validation prediction error wins. BLME uses the numerical floor when the inner split has fewer than two fit tokens or no validation tokens.

BLME then refits the thresholds, means and affine map on all outer training documents. It retains singular values strictly above the chosen cutoff times the largest training singular value. The numerical floor drops covariance eigenvalues at or below float32 epsilon relative to the largest. A rank-zero fit predicts the training target mean.

The test R² for each adjacent pair is one minus its squared prediction error divided by the squared error of predicting the training target mean. The headline averages finite pair scores equally. Negative values mean the affine map did worse than the training-mean predictor. The `_meta_procrustes_heldout` entry records both document splits and token counts, the selection rule, the selected cutoff, rank and R² for each pair, and the reason for an undefined result. The in-sample and released-notebook scores have separate definitions above.

For a readout-only backfill, the task config accepts `heldout_only: true`. Set `heldout_gram_device` to `cpu` or `cuda` for the float64 Gram fit. Direct SVD is the default and handles ambiguous numerical cutoffs. Both fits use the same documents, training-selected ranks and held-out targets.

## 33. Superposition Strength (geometry_superposition_strength)
* **What are we measuring**: How tightly the unembedding packs V vocabulary directions into m ≪ V dimensions — the degree of representation superposition, normalized by the information-theoretic packing optimum.
* **How are we measuring**: Mean squared cosine overlap E_{i≠j}[cos²(W_i, W_j)] over row pairs of the raw row-normalised LM head (all pairs when feasible, otherwise a seeded sample of `max_pairs: 200000`), and its ratio to the Welch bound κ² = (V - m) / (m(V - 1)). Also reported: a mean-centred variant, which removes the shared anisotropy direction, and row-norm dispersion statistics.
* **Hypothesis**: Per Liu-Liu-Gore, LLMs operate in the STRONG-superposition regime — overlap ≈ the Welch/1/m optimum (ratio ≈ 1–2) — and this packing regime underlies robust neural scaling; departures flag under-utilized representation capacity.
* **Citation/Paper**: `Liu, Y., Liu, Z., & Gore, J. (2025). Superposition Yields Robust Neural Scaling.` [NeurIPS 2025, ArXiv: 2505.10465]
* **Paper summary**: Liu et al. build toy models spanning weak→strong superposition and show the neural-scaling exponent is governed by the superposition regime: under strong superposition, loss scales robustly as ~1/m regardless of the feature-frequency distribution, because representation vectors pack near the geometric overlap floor. They verify that open-weight LLMs (GPT-2, Pythia, OPT, Qwen) sit in the strong regime: the mean squared overlap of their LM-head vectors follows the ~1/m Welch scaling across model widths, and connect this to the observed ~1/m loss-scaling of real LLM families.
* **File & Function**: `src/blme/tasks/geometry/superposition_strength.py` -> `SuperpositionStrengthTask`
* **Critical Info**: Headline keys: `mean_squared_overlap`, `mean_squared_overlap_centered`, `superposition_ratio`, `superposition_ratio_centered`, `row_norm_cv`, `frac_norm_above_half_max`. Declared invariant: `mean_squared_overlap`, `mean_squared_overlap_centered`, `row_norm_cv`, `frac_norm_above_half_max` to zero-padding the width and unused vocabulary rows (`tests/tasks/invariance/test_superposition_strength.py::test_size_invariant_entry`); `superposition_ratio`, `superposition_ratio_centered` to unused vocabulary rows (`tests/tasks/invariance/test_superposition_strength.py::test_size_invariant_entry`). Weights only. The headline uses raw rows, as the official code does. On LLM heads the shared anisotropy direction can dominate the raw value, which is why the centred variant is reported beside it.

## 34. Effective Depth / Block Influence (geometry_effective_depth)
* **What are we measuring**: How much each transformer layer actually transforms the residual stream, and how much of the network's depth does real work.
* **How are we measuring**: Block Influence BI_l = 1 - E_t[cos(h_(l,t), h_(l+1,t))] per block (ShortGPT), over every token of each sample; `total_block_influence` and `max_block_influence` are its sum and maximum over blocks. `effective_depth_90` is the smallest fraction of depth at which the cumulative contribution reaches 90% of the total.
* **Hypothesis**: Trained LMs contain redundant, near-identity layers (especially late-middle ones); low effective depth signals wasted capacity — such layers can be pruned with little performance loss (ShortGPT) and models "use their depth" far from fully (Csordás).
* **Citation/Paper**: `Men, X., et al. (2024). ShortGPT: Layers in Large Language Models are More Redundant Than You Expect.` [ArXiv: 2403.03853]; `Csordás, R., Manning, C. D., & Potts, C. (2025). Do Language Models Use Their Depth Efficiently?` [NeurIPS 2025, ArXiv: 2505.13898]
* **Paper summary**: Men et al. define Block Influence — one minus the expected token-wise cosine between a block's input and output — rank layers by it, and show that simply deleting the lowest-BI ~25% of layers of Llama-2/Baichuan barely hurts benchmarks, beating contemporary pruning methods; redundancy concentrates in later-middle layers. Csordás et al. analyze residual-stream contributions and find the second half of layers in modern LLMs contributes far less and mostly refines existing features rather than computing new ones — i.e., models under-utilize their depth; they quantify this with cumulative-contribution profiles across depth (the shape BLME's `effective_depth_90` summarizes).
* **File & Function**: `src/blme/tasks/geometry/effective_depth.py` -> `EffectiveDepthTask`
* **Critical Info**: Headline keys: `effective_depth_90`, `total_block_influence`, `max_block_influence`. Declared invariant: `total_block_influence`, `max_block_influence` to identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_effective_depth.py::test_depth_additive_keys_under_identity_blocks`). The task runs its own forward pass and hooks the last block's output before the final norm, so the last block's influence does not include the final norm. `effective_depth_90` is a BLME summary inspired by Csordás et al.; their own statistic is an importance-weighted depth score. The `frac_low_influence` threshold (0.05) is a BLME choice. Defaults: `num_samples: 20`, `max_length: 512`. The contribution of block l is the mean over tokens of the relative update ‖h_(l+1) − h_l‖ / ‖h_l‖ (Csordás et al., `analyze_norms.py`), not Block Influence. On gpt2 and pythia block 0 alone carries 59–69% of the total, so `effective_depth_90` takes only a couple of values (11/12 or 12/12) on small models.

## 35. alpha-ReQ and RankMe (geometry_alpha_req)
* **What are we measuring**: How fast the covariance spectrum of the model's sequence representations decays (alpha-ReQ, the exponent of a power law λ_i ∝ i^−α), and its effective rank (RankMe).
* **How are we measuring**: One point per sequence, the model output state (HF's final hidden state) of the last token of a 20-word window of each of 1000 passages (the same words for every model, as in Cheng et al. 2024). Eigenvalues are the PCA explained-variance ratios of the centred cloud; alpha is a weighted least-squares fit of log λ on −log rank over ranks 11-100 (weights 1/rank); RankMe = exp(−Σ p log p) with p = λ/Σλ + 1e-7. `profile: true` adds per-block-output profiles.
* **Hypothesis**: A small alpha (flat spectrum, many directions in use) and a high RankMe mark richer representations; Li et al. find both track phases of pretraining and post-training within a model.
* **Citation/Paper**: `Agrawal, K. K., et al. (2022). α-ReQ: Assessing Representation Quality in Self-Supervised Learning by measuring eigenspectrum decay.` [NeurIPS 2022]; `Garrido, Q., et al. (2023). RankMe: Assessing the Downstream Performance of Pretrained Self-Supervised Representations by Their Rank.` [ICML 2023, ArXiv: 2210.02885]; `Li, M. Z., et al. (2025). Tracing the Representation Geometry of Language Models from Pretraining to Post-training.` [NeurIPS 2025, ArXiv: 2509.23024]
* **Paper summary**: Agrawal et al. show that the eigenspectrum decay of self-supervised vision representations predicts linear-probe quality without labels. Li et al. apply alpha-ReQ and RankMe to the last-token, last-layer representations of OLMo-2 and Pythia checkpoints (15000 FineWeb sequences) and describe three geometric phases of pretraining and opposite effects of SFT and RLVR.
* **File & Function**: `src/blme/tasks/geometry/alpha_req.py` -> `AlphaReQTask`
* **Critical Info**: Headline keys: `alpha_req`, `rankme`. Declared invariant: `alpha_req` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior) (`tests/tasks/invariance/test_geometry_alpha_req.py::test_headline_invariant`); `rankme` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_alpha_req.py::test_headline_invariant`). N is the same 1000 sequences for every model (Li et al. use 15000 and report robustness to the sample count). Fewer than 100 eigenvalues (N or d below 100) gives alpha = NaN with `_meta_alpha_req_skipped_reason`. RankMe adds 1e-7 to every normalised eigenvalue, so extra zero eigenvalues change it only negligibly. RankMe here is computed on covariance eigenvalues (Li et al.; reptrix), not Garrido et al.'s singular values: on gpt2 the three rogue coordinates hold 41/20/14% of the variance, so RankMe is 3.46 (226 with singular values).

## 36. Spectral Signature / PL_Alpha_Hill (geometry_spectral_signature)
* **What are we measuring**: The heavy-tail exponent of every weight matrix's eigenvalue spectrum, with the estimator the HT-SR LLM literature uses (PL_Alpha_Hill, xmin = the median eigenvalue), and its mean and median over the model.
* **How are we measuring**: Eigenvalues of W^T W (squared float32 singular values) above 1e-5, sorted; xmin at index N//2; alpha = 1 + n / (Σ_{j≥i} log λ_j − n log λ_i). Matrices as the released Spectral Signature code selects them: Linear and HF Conv1D weights (torch convolutions are skipped, so its Conv2d branch never runs); Linear weights with aspect ratio ≥ 8 (the LM head) skipped; attention weights with a 1:3 shape split into three contiguous row blocks (on GPT-NeoX's per-head interleaved query_key_value these are head-group mixtures, not Q, K and V; the rule also fires on some sizes of a family and not others, e.g. Qwen3.5-2B's linear-attention in_proj_qkv only); packed 3-D expert weights split per expert.
* **Hypothesis**: Heavier tails (smaller alpha) mark better-trained matrices (HT-SR); the profile is a lineage fingerprint (Zhang et al. 2026).
* **Citation/Paper**: `Zhang, Z., et al. (2026). Spectral Signatures of Large Language Models.` [ArXiv: 2607.03377]; `Lu, H., et al. (2024). AlphaPruning: Using Heavy-Tailed Self Regularization Theory for Improved Layer-wise Pruning of Large Language Models.` [NeurIPS 2024, ArXiv: 2410.10912]
* **Paper summary**: Zhang et al. fingerprint 499 Open LLM Leaderboard models by their per-matrix PL_Alpha_Hill profiles and compare models by the Spearman correlation of aligned profiles. AlphaPruning allocates layer-wise sparsity from the same per-matrix alphas.
* **File & Function**: `src/blme/tasks/geometry/spectral_signature.py` -> `SpectralSignatureTask`
* **Critical Info**: Headline keys: `alpha_hill_mean`, `alpha_hill_median`. No key is declared size-invariant. The per-model profile and module names are `_meta_` (the release's similarity needs two models). Two departures from the release, counted in `_meta_`: torch convolution kernels are skipped, and only the language model is scanned (a multimodal checkpoint's vision tower is left out). The release's shape rule also splits a GQA key/value projection whose width is a third of the hidden size; BLME keeps that. The mean moves under identity-block insertion and the 1e-5 cut is not scale-free.

## 37. GRIDE Intrinsic-Dimension Profile (geometry_gride)
* **What are we measuring**: The intrinsic dimension of the sequence representations at a controlled neighbour scale, at every layer, and the height of its peak (Cheng et al.'s high-dimensional "abstraction phase").
* **How are we measuring**: One point per sequence (the last token of a 20-word window of each of 1000 passages, the same words for every model) at every HF hidden state after the embeddings. Identical points removed; for n1 = 1, 2, 4, ... the ratios mu = r_{2 n1} / r_{n1} of each point's neighbour distances give a maximum-likelihood ID (GRIDE); the headline profile is at n2 = 4, the scaling profile per layer is `_meta_`.
* **Hypothesis**: An intermediate high-ID phase marks where models build abstract representations; an earlier onset goes with better language modelling (Cheng et al.).
* **Citation/Paper**: `Cheng, E., et al. (2025). Emergence of a High-Dimensional Abstraction Phase in Language Transformers.` [ICLR 2025, ArXiv: 2405.15471]; `Denti, F., et al. (2022). The generalized ratios intrinsic dimension estimator.` [Sci. Rep. 12:20005]
* **Paper summary**: Cheng et al. measure GRIDE ID of last-token representations at every layer of five LLMs on three corpora, find a pronounced intermediate peak, and relate its onset to surprisal and its layers to probing transfer.
* **File & Function**: `src/blme/tasks/geometry/gride.py` -> `GrideProfileTask`
* **Critical Info**: Headline keys: `gride_id_peak`, `gride_id_last_layer`. Declared invariant: `gride_id_peak` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior) (`tests/tasks/invariance/test_geometry_gride.py::test_headline_invariant`); `gride_id_last_layer` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_gride.py::test_headline_invariant`). Cheng et al. use 10000 sequences and choose the scale by eye; BLME uses N = 1000 and n2 = 4 for every model. The deepest entry is HF's post-norm output state, as in the released scripts. The peak's layer position is `_meta_`, because it moves when blocks are added.

## 38. Information Imbalance (geometry_information_imbalance)
* **What are we measuring**: Whether one layer's neighbourhoods predict another's, in each direction (Glielmo et al.'s information imbalance), between the first and the last layer.
* **How are we measuring**: Delta(A->B) = mean rank, in B, of each point's nearest neighbour in A, divided by N/2 (k = 1, Euclidean, full-rank neighbour lists), on the last token of a 20-word window of each of 1000 passages. Headline: Delta(first->last), Delta(last->first) and their difference; the profiles to and from the last layer are kept.
* **Hypothesis**: An asymmetric imbalance shows which representation contains the other's information; CKA, CKNNA, RSA and HSIC are all symmetric.
* **Citation/Paper**: `Glielmo, A., et al. (2022). Ranking the information content of distance measures.` [PNAS Nexus, ArXiv: 2104.15079]; `Cheng, E., et al. (2025).` [ICLR 2025, ArXiv: 2405.15471]
* **Paper summary**: Glielmo et al. define the information imbalance as an asymmetric, rank-based comparison of two distance measures; Cheng et al. use it between the layers of an LLM and across models.
* **File & Function**: `src/blme/tasks/geometry/gride.py` -> `InformationImbalanceTask`
* **Critical Info**: Headline keys: `ii_first_to_last`, `ii_last_to_first`, `ii_asymmetry_first_last`. All of them are declared invariant to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, trailing) (`tests/tasks/invariance/test_geometry_gride.py::test_headline_invariant`). Full-rank neighbour lists make the release's random rank for a missing neighbour impossible, so the value is deterministic. Values for the index-selected middle layer are `_meta_`. The asymmetry is Δ(last → first) − Δ(first → last), with "first" = `hidden_states[1]`.

## 39. FARMS alpha (geometry_farms_alpha)
* **What are we measuring**: The heavy-tail exponent of every weight matrix's eigenvalue spectrum measured on fixed-aspect-ratio windows of the matrix, so that the matrix's own aspect ratio does not bias it, and its mean over the model.
* **How are we measuring**: The released FARMS LLM configuration. Each matrix is cut into at most 15 x 15 windows of r = min(2000, rows, cols) rows by r columns (Q = 1) on a regular grid; the squared float32 singular values of all windows are pooled and sorted. A 100-bin histogram of log10 of the pooled eigenvalues locates the peak bin's left edge p; every eigenvalue in [log10(0.95 p), 1.5 p] (the release compares the log10-unit lower bound with linear eigenvalues; kept) is a candidate xmin with Hill exponent alpha = 1 + n / (Σ_{j≥i} log λ_j − n log λ_i) and KS distance D; the alpha of the smallest D is the matrix's. Matrices: every nn.Linear in the transformer blocks (the release's population) plus HF Conv1D weights as their Linear equivalent W.T. `farms_alpha_mean_w512` repeats the fit with 512 x 512 windows for every model.
* **Hypothesis**: HT-SR: heavier-tailed (smaller alpha) matrices are better trained; FARMS makes the per-matrix alphas comparable across matrices of different shapes (Hu et al. use them to allocate layer-wise learning rates and pruning sparsity).
* **Citation/Paper**: `Hu, Y., Goel, K., Killiakov, V., & Yang, Y. (2025). Eigenspectrum Analysis of Neural Networks without Aspect Ratio Bias.` [ICML 2025, PMLR 267:24290-24313, ArXiv: 2506.06280]; `Lu, H., et al. (2024). AlphaPruning: Using Heavy-Tailed Self Regularization Theory for Improved Layer-wise Pruning of Large Language Models.` [NeurIPS 2024, ArXiv: 2410.10912]
* **Paper summary**: Hu et al. show that the HT-SR exponent of a whole weight matrix depends on its aspect ratio and replace the whole-matrix spectrum with the average spectrum of fixed-aspect-ratio submatrices (Fixed-Aspect-Ratio Matrix Subsampling). The released code applies it to layer-wise learning-rate balancing in image classification (TempBalance), to layer-wise sparsity allocation when pruning LLaMA-7B/13B (AlphaPruning) and to SciML.
* **File & Function**: `src/blme/tasks/geometry/farms.py` -> `FARMSAlphaTask`
* **Critical Info**: Headline keys: `farms_alpha_mean`, `farms_alpha_mean_w512`. No key is declared size-invariant. Weights only. Departures from the release: HF Conv1D weights are included (the release's `isinstance(m, nn.Linear)` cannot see GPT-2's projections; GPT-2's fused `c_attn` is one matrix), and a matrix with a zero or non-finite pooled eigenvalue gets alpha = NaN with a reason (the release's `torch.histc` raises there; a zero-padded matrix is such a case). Packed MoE expert tensors and torch conv kernels are not measured and are counted in `_meta_n_packed_expert_tensors` / `_meta_n_other_weight_tensors_unmeasured`, so on an MoE model the headline covers the attention and shared weights only. The w512 twin is a BLME choice: the release's window side grows with width up to 2000; the twin does not fix matrices narrower than 512, the window covering a smaller share of a wider matrix, or the mean's dependence on the number of matrices. The release's fit is kept as released and is fragile: the KS optimum often sits at the upper candidate cap, and a near-tie between the two highest histogram bins can move the peak by a bin; `_meta_n_peak_bin_near_tie` and `_meta_n_xmin_at_candidate_cap` count the exposed matrices. Results can differ slightly between CPU and GPU runs and with the thread count. Most of the cost is window SVDs.

## 40. Representation dispersion (geometry_representation_dispersion)
* **What are we measuring**: How spread out the model's final representations of different text segments are: the mean pairwise cosine distance between them.
* **How are we measuring**: The released protocol. The WikiText-103 validation rows are joined with blank lines and tokenized without special tokens; every full 512-token chunk (at most 10000, sampled with seed 42) is run through the model, and its last token's final hidden state (after the final norm) is kept. Dispersion is mean_{i<j} (1 - cos(x_i, x_j)), in float32.
* **Hypothesis**: Li et al. find that within a model, segments the model predicts well have more dispersed representations, and that dispersion tracks downstream accuracy across fine-tuned variants of one family.
* **Citation/Paper**: `Li, Y., et al. (2026). On the Predictive Power of Representation Dispersion in Language Models.` [ICLR 2026, ArXiv: 2506.24106]; code yanhong-lbh/rep_dispersion.
* **File & Function**: `src/blme/tasks/geometry/dispersion.py` -> `RepresentationDispersionTask`
* **Critical Info**: Headline key: `representation_dispersion`. It is declared invariant to identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_representation_dispersion.py::test_headline_invariant`). Each chunk is scored once; the 10000-chunk cap does not bind on WikiText-103 validation. The release reads the tokenized WikiText-103 variant; BLME reads the raw one the library caches. Without special tokens a model trained with a BOS never sees it, as in the release; `_meta_tokenizer_adds_bos` marks those models. The paper's analysis bins segments by perplexity within a model; this task reports one model-level number. It is close to `geometry_vendi_score`, which summarises the spectrum of a cosine Gram matrix instead of its mean.

## 41. Predictive information (geometry_predictive_information)
* **What are we measuring**: How much each layer's representation of a context tells about the token that comes next, as a mutual information I(Z_l; Y) across depth.
* **How are we measuring**: The released InfoRidge estimator. Each of 1000 corpus passages is split at a seeded random position; Z_l is the layer-l state of the last context token (HF hidden states 1..L) and Y the embedding-layer output of the true next token. Rows are L2-normalised, a Gaussian kernel (sigma = 1) gives each cloud's Gram matrix, and I(Z; Y) = H(Z) + H(Y) - H(Z, Y) with matrix-based von Neumann entropies, the joint from the Hadamard product of the trace-normalised Grams.
* **Hypothesis**: Chang et al. find that predictive information peaks in intermediate layers (a "generalization ridge") and declines in the final layers, which they read as a move from generalization to memorization.
* **Citation/Paper**: `Chang, R., et al. (2026). The Generalization Ridge: Information Flow in Natural Language Generation.` [COLM 2026, ArXiv: 2507.05387]; code chili-lab/InfoRidge.
* **File & Function**: `src/blme/tasks/geometry/predictive_information.py` -> `PredictiveInformationTask`
* **Critical Info**: Headline keys: `predictive_info_peak`, `predictive_info_peak_depth`, `predictive_info_last_layer`. Declared invariant: `predictive_info_peak` to identity blocks (interior) (`tests/tasks/invariance/test_geometry_predictive_information.py::test_headline_invariant`); `predictive_info_last_layer` to identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_predictive_information.py::test_headline_invariant`). Each passage is scored once, plus two 1000 x 1000 eigendecompositions per layer. The MI is bounded by log N, so N is 1000 for every model (`_meta_log_n`). The estimator is far from 0 for independent clouds (the Gaussian kernel on unit vectors is flat), so compare values at the same N and sigma only. The release scores question/answer pairs; BLME uses natural-text next tokens. Y is the model's own input embedding, so tied and untied heads, and position embeddings (GPT-2), enter it. `predictive_info_peak_depth` is argmax / L and moves when blocks are inserted. A block before block 0 or after the last one adds a new state (the embedding output, or the pre-norm last state), which can move the peak (`tests/tasks/invariance/test_end_of_stack_identity_blocks.py`). Each of the first 1000 passages is split at one position drawn uniformly from [8, T − 1] by Python's `random.Random(split_seed)` (`split_seed: 0`); the tokens before it are Z, the rest Y. On gpt2 and pythia the post-norm last layer is nearly collinear (anisotropy 0.90–0.95), so its MI collapses (0.09 / 0.19 against peaks of 1.2 / 2.2); Llama's does not.

## 42. Neighbourhood overlap (geometry_neighborhood_overlap)
* **What are we measuring**: How much each point's local neighbourhood is preserved between layers: the mean fraction of its k = 30 nearest neighbours shared by two layers.
* **How are we measuring**: DADApy's `return_data_overlap` on the clouds of `geometry_gride` (the last token of a 20-word window of each of 1000 passages at every HF hidden state after the embeddings), between every layer and the last and between adjacent layers.
* **Hypothesis**: Doimo et al. and Valeriani et al. use the overlap to find where representations reorganise; a low first-to-last overlap means the output geometry is far from the input's, and a low adjacent minimum marks a layer where neighbourhoods change abruptly.
* **Citation/Paper**: `Doimo, D., Glielmo, A., Ansuini, A., & Laio, A. (2020). Hierarchical nucleation in deep neural networks.` [NeurIPS 2020, ArXiv: 2007.03506]; `Valeriani, L., et al. (2023). The geometry of hidden representations of large transformer models.` [ArXiv: 2302.00294]; code DADApy.
* **File & Function**: `src/blme/tasks/geometry/gride.py` -> `NeighborhoodOverlapTask`
* **Critical Info**: Headline keys: `nn_overlap_first_last`, `nn_overlap_adjacent_min`. Declared invariant: `nn_overlap_first_last` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior, trailing) (`tests/tasks/invariance/test_geometry_gride.py::test_headline_invariant`); `nn_overlap_adjacent_min` to zero-padding the width, isometric re-embedding, a global rescale and identity blocks (interior) (`tests/tasks/invariance/test_geometry_gride.py::test_headline_invariant`). It shares `geometry_cknna`'s mutual-kNN idea, so expect them to correlate. Identity blocks between existing blocks add adjacent pairs with overlap 1; the mean adjacent overlap therefore moves and is `_meta_`. At the ends of the stack a block before block 0 adds the embedding state and one after the last block adds the pre-norm state next to its final norm, and either can move a key (`tests/tasks/invariance/test_end_of_stack_identity_blocks.py`). `neighborhood_overlap_adjacent_min` is the last pair on gpt2 and pythia, the only pair that includes the final norm.

## 43. WeightWatcher Randomized and MP-Fit Metrics (geometry_ww_randomized)
* **What are we measuring**: How far each weight matrix's eigenvalue spectrum is from the spectrum of its own element-shuffled copy (learned correlation structure, which a shuffle destroys), how many eigenvalues escape the fitted Marchenko-Pastur (MP) bulk, how far the bulk edge sits below the largest eigenvalue, the share of eigenvalues below the bulk's lower edge, and SETOL's det X = 1 tail, each averaged over the model's weight matrices.
* **How are we measuring**: WeightWatcher's `analyze(randomize=True, mp_fit=True, detX=True)`, ported function by function. For W (N x M, N ≥ M, Q = N/M) with eigenvalues λ of WᵀW (squared float64 singular values): `rand_distance` = `jensen_shannon_distance(λ, λ_rand)`, where λ_rand are the eigenvalues of W with its entries shuffled; the release applies `scipy.stats.entropy` to the two sorted eigenvalue vectors (normalised over the index), not to histograms. `ww_softrank` = max λ_rand / max λ. `mp_fit`: λ rescaled to mean 1, a linear-kernel KDE (bandwidth 0.1) fitted by brute force plus Nelder-Mead to the MP density of aspect ratio Q (quarter-circle law on the singular values at Q = 1); `num_spikes` = #{λ > λ₊ + √TW}, `mp_softrank` = λ₊ / λ_max, `bulk_min` = λ₋. `apply_detX`: λ rescaled to mean 1, `detX_num` = the length of the first top suffix whose product is below 1, `ERG_gap` = detX_num − num_pl_spikes (λ ≥ the KS-optimal power-law xmin of WWFit). Headlines, means over matrices: `rand_distance_mean` (the permutation-null distance, the release's randomization metric), `ww_softrank_mean` (the top eigenvalue against the shuffled null's), `mp_softrank_mean` (the same against the fitted bulk edge, free of the shuffle), `spike_fraction_mean` (num_spikes / M, the size-independent twin of the release's count), `frac_below_bulk_min_mean` (the Staats et al. lower edge, below). Matrices: the language model's Linear and HF Conv1D weights (as `geometry_spectral`) that the release's `layer_supported` admits (8 ≤ M ≤ 15000, N ≤ 50000).
* **Hypothesis**: HT-SR / SETOL: a trained layer's correlations push eigenvalues out of the bulk and away from its randomized null (large rand_distance, small soft ranks); outliers in the randomized spectrum (correlation traps) accompany over-fitting and generalization collapse (Prakash & Martin); ERG_gap measures how far SETOL's det X = 1 tail is from the power-law tail, which SETOL reports agree closely. Staats et al. find that eigenvalues departing from random-matrix theory at the small end of the spectrum carry signal too.
* **Citation/Paper**: `Prakash, H. K., & Martin, C. H. (2025). Grokking and Generalization Collapse: Insights from HTSR theory.` [ArXiv: 2506.04434]; `Martin, C. H., & Hinrichs, C. (2025). SETOL: A Semi-Empirical Theory of (Deep) Learning.` [ArXiv: 2507.17912]; `Staats, M., Thamm, M., & Rosenow, B. (2024). Small Singular Values Matter: A Random Matrix Analysis of Transformer Models.` [ArXiv: 2410.17770]; `Martin, C. H., & Mahoney, M. W. (2021). Implicit Self-Regularization in Deep Neural Networks.` [JMLR 22, ArXiv: 1810.01075]
* **Paper summary**: Prakash & Martin follow WeightWatcher's HT-SR metrics through grokking of a 3-layer MLP trained on 1000 MNIST samples and identify a late anti-grokking phase, in which test accuracy collapses while training accuracy stays perfect, marked by alpha < 2 and by correlation traps (outliers in the spectrum of the randomized layer weight matrix). SETOL grounds the HT-SR alpha and alpha-hat metrics in statistical mechanics and random-matrix theory and introduces an ERG condition, tied to one step of Wilson's exact renormalization group, which the release evaluates as the det X = 1 tail; on a 3-layer MLP and on state-of-the-art pretrained models ERG and alpha align closely. Staats et al. compare transformer weight spectra with random-matrix theory and find departures among both the largest and the smallest singular values; zeroing the small singular values that deviate from RMT raises perplexity more than removing bulk ones.
* **File & Function**: `src/blme/tasks/geometry/ww_randomized.py` -> `WWRandomizedTask`
* **Critical Info**: Headline keys: `rand_distance_mean`, `ww_softrank_mean`, `mp_softrank_mean`, `spike_fraction_mean`, `frac_below_bulk_min_mean`. No key is declared size-invariant. Weights only. Departures from the release: the shuffle uses `np.random.RandomState(shuffle_seed)` (default 42) instead of the unseeded global `np.random`, consumed in the release's order; the release's -1 sentinels of a failed MP or power-law fit become NaN, counted in `_meta_`; torch conv kernels are skipped. The release's path without CUDA is followed (float32 weights, float64 scipy SVDs). `frac_below_bulk_min` is a BLME composition: Staats et al. do not use WeightWatcher's fit, and the fraction is NaN for square matrices. A vocabulary head above 50000 rows is skipped, as the release skips it. A release defect is kept and measured: `detX_num` multiplies an ascending float64 suffix smallest-first and can underflow on large matrices, so `_meta_detX_num_logsum` / `_meta_ERG_gap_logsum` take each product as a sum of logs and `_meta_n_detX_float_mismatch` counts the affected matrices. The MP fit can lock onto a cluster of near-zero eigenvalues. Counts (num_spikes, detX_num, ERG_gap) grow with width, so their fractions of M are reported.

## 44. Rogue dimensions (geometry_rogue_dimensions)
* **What are we measuring**: How much of the representations' anisotropy (the mean cosine similarity of random token pairs) a few coordinates carry.
* **How are we measuring**: The release's readout: the first 128 tokens of each of 150 articles, tokenized without special tokens, every token at every HF hidden state. Each coordinate's contribution to the cosine similarity of token pairs, CC_i = E[u_i v_i / (|u||v|)], is computed exactly over all distinct pairs (the release samples 500000); the shares of the largest one and three contributions in their sum are reported per layer.
* **Hypothesis**: Timkey & van Schijndel find that one to three "rogue" dimensions dominate the cosine similarity of GPT-2 and BERT-family representations, so cosine-based measures mostly read those dimensions rather than the representation as a whole.
* **Citation/Paper**: `Timkey, W., & van Schijndel, M. (2021). All Bark and No Bite: Rogue Dimensions in Transformer Language Models Obscure Representational Quality.` [EMNLP 2021, ArXiv: 2109.04404]; code wtimkey/rogue-dimensions.
* **File & Function**: `src/blme/tasks/geometry/rogue_dimensions.py` -> `RogueDimensionsTask`
* **Critical Info**: Headline keys: `rogue_top1_share_max`, `rogue_top3_share_max`, `rogue_top1_share_last`. Declared invariant: `rogue_top1_share_max`, `rogue_top3_share_max` to identity blocks (interior, leading) (`tests/tasks/invariance/test_geometry_rogue_dimensions.py::test_headline_invariant`); `rogue_top1_share_last` to identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_rogue_dimensions.py::test_headline_invariant`). Rogue dimensions are coordinates, so the shares change under a rotation of the basis. The shares are unstable where the anisotropy is near 0 (NaN when it is not positive). The first token of each document is often an attention sink; `_meta_rogue_top1_share_profile_without_first_token` drops it. The 150 articles are `load_long_documents(150, split="train")`.

## 45. LM-head spectral free energy (geometry_lm_head_free_energy)
* **What are we measuring**: How unequal the spectrum of the output unembedding is, as a Bayesian free energy of the weight matrix.
* **How are we measuring**: The released BFE-W: e = the eigenvalues of W.T @ W of the output unembedding (float32), lambda = 1 / mean(e), BFE-W = lambda/2 mean(e) - 1/2 mean(log e) + 1/2 log(2 pi / lambda), which equals half the log ratio of the arithmetic to the geometric mean of e plus a constant.
* **Hypothesis**: Wilson reports that within a model family BFE-W of the unembedding tracks benchmark quality (Pythia with LAMBADA, Qwen3.5 with MMLU-Pro).
* **Citation/Paper**: `Wilson, J. (2026). Why Heavy-Tailed Weight Spectra Predict Model Quality.` [NeurIPS 2026, ArXiv: 2610.13123]; code josephwilsonmaths/heavytail.
* **File & Function**: `src/blme/tasks/geometry/lm_head_free_energy.py` -> `LMHeadFreeEnergyTask`
* **Critical Info**: Headline key: `lm_head_bfe_w`. It is declared invariant to identity blocks (interior, leading, trailing) (`tests/tasks/parity/test_lm_head_free_energy_parity.py::test_headline_invariant_under_identity_blocks`). Weights only; one d x d Gram. The float32 Gram loses the smallest eigenvalues of an ill-conditioned head, so `_meta_lm_head_bfe_w_float64` reports the float64 value. Expect a strong correlation with `geometry_unembedding`'s effective rank, which reads the same spectrum. Undefined (NaN) when the head is rank-deficient, as for a zero-padded width.

## 46. DiME augmentation invariance (geometry_dime)
* **What are we measuring**: Whether two surface-perturbed views of the same text land at matching points of each layer's representation space, as DiME, a mutual-information-like difference of matrix-based entropies, across depth.
* **How are we measuring**: The released protocol of Skean et al. Each of the first 1000 corpus passages with at least 30 tokens is augmented twice by nlpaug's SplitAug -> RandomCharAug -> KeyboardAug chain at its defaults (30% of the words, at most 10 per augmenter). Each view runs through the model on its own and its tokens are averaged at every HF hidden state, from the embedding output to the post-final-norm state. Per layer and view the N pooled rows are centred and L2-normalised; with K_A and K_B their N x N Gram matrices, DiME = E_P[H(K_A o P K_B P^T)] - H(K_A o K_B), where H is the von Neumann entropy (alpha = 1), o the Hadamard product and P one of 10 seeded permutations of the prompts (representation-itl `doe`).
* **Hypothesis**: Skean et al. find that intermediate layers often give better embeddings than the last, and that augmentation-invariance metrics such as DiME track downstream (MTEB) performance across the layers of a model. A high DiME means the two views of a prompt are closer to each other than to the views of other prompts.
* **Citation/Paper**: `Skean, O., Arefin, M. R., Zhao, D., Patel, N., Naghiyev, J., LeCun, Y., & Shwartz-Ziv, R. (2025). Layer by Layer: Uncovering Hidden Representations in Language Models.` [ICML 2025, ArXiv: 2502.02013]; `Skean, O., et al. (2023). DiME: Maximizing Mutual Information by a Difference of Matrix-Based Entropies.` [ArXiv: 2301.08164]; code OFSkean/information_flow and uk-cliplab/representation-itl.
* **File & Function**: `src/blme/tasks/geometry/dime.py` -> `DiMETask`
* **Critical Info**: Headline keys: `dime_peak`, `dime_last_layer`, `dime_peak_depth`. Declared invariant: `dime_peak` to zero-padding the width and identity blocks (interior, leading) (`tests/tasks/invariance/test_geometry_dime.py::test_headline_invariant`); `dime_last_layer` to zero-padding the width and identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_dime.py::test_headline_invariant`). On models with a BOS the all-token mean pool carries the BOS state divided by the view's length, which the two views of a prompt share, so part of the headline measures equal lengths; `_meta_dime_profile_without_pos0` is the twin to compare models with and without a BOS. Needs `nlpaug` (`pip install nlpaug==1.1.11`); without it the task returns an error. The cost is 2N forward passes plus 11 N x N eigendecompositions per hidden state. DiME is in nats and at most log N; N is the 1000 passages minus those under 30 tokens (`_meta_n_prompts`, which depends on the tokenizer). When N > D the release passes the D x D covariance instead of the Gram and then permutes features instead of prompts; BLME uses the Gram for every model and reports the release's value as `_meta_dime_release_profile`. Other departures from the release: centring over all N, unpadded views, and the augmented text itself as input. Character noise changes the token count differently per tokenizer. `dime_peak_depth` (argmax / L) moves when blocks are inserted; a block after the last one adds the pre-norm state, which can move the peak (`tests/tasks/invariance/test_end_of_stack_identity_blocks.py`).

## 47. Zipfian symmetry (geometry_zipfian_symmetry)
* **What are we measuring**: How centred and how isotropic the input embedding and the unembedding tables are once each token is weighted by how often it is used.
* **How are we measuring**: The released scores. With p(w) the unigram probability of token w (each model's own tokens counted over the library corpus) and W the rows of the tokens that occur: Sym1 = 1 - |E_p[w]| / E_p[|w|], and Sym2 = the entropy of the normalised spectrum of sqrt(p)(W - E_p[w]) divided by log d. The uniform versions (p = 1/n on the same rows) are reported alongside.
* **Hypothesis**: Yokoi et al. argue that word frequency is the right measure for an embedding space: tables that look anisotropic under a uniform average can be symmetric under the Zipfian one, and the Zipfian symmetry is what downstream similarity reflects.
* **Citation/Paper**: `Yokoi, S., et al. (2024). Zipfian Whitening.` [NeurIPS 2024, ArXiv: 2411.00680]; code cl-tohoku/zipfian-whitening.
* **File & Function**: `src/blme/tasks/geometry/zipfian_symmetry.py` -> `ZipfianSymmetryTask`
* **Critical Info**: Headline keys: `zipf_sym1_embedding`, `zipf_sym2_embedding`, `zipf_sym1_unembedding`, `zipf_sym2_unembedding`. All of them are declared invariant to identity blocks (interior, leading, trailing) (`tests/tasks/parity/test_zipfian_symmetry_parity.py::test_headline_invariant_under_identity_blocks`). Weights plus one tokenisation of the corpus; one SVD per table. The paper's experiments are on static word embeddings, not LLM tables. Sym2's division by log d moves when the width is zero-padded; `_meta_zipf_spectral_entropy_*` is the undivided entropy. Tied models give identical embedding and unembedding scores. Token frequencies come from the full 1691-passage default corpus, whatever dataset is passed.

## 48. Delta-hyperbolicity (geometry_delta_hyperbolicity)
* **What are we measuring**: How tree-like the geometry of one prompt's token cloud is, from the input embeddings through every layer.
* **How are we measuring**: The released estimator: Euclidean distances, Gromov products at the first point as base point, delta = max over pairs of (max_z min((x|z), (z|y)) - (x|y)), reported as 2 delta / diam and averaged over prompts. The headline input-embedding value uses the release's cloud (the embedding lookup of the prompt's tokens); the profile applies the same estimator to every hidden state without position 0. Every cloud has the first 64 tokens of a passage of at least 1000 bytes.
* **Hypothesis**: Yang et al. find that LLM token embeddings are strongly hyperbolic (low relative delta) and use it to motivate hyperbolic fine-tuning; the Atlas reports that depth changes delta more than scale does.
* **Citation/Paper**: `Yang, M., et al. (2025). Hyperbolic Fine-Tuning for Large Language Models.` [NeurIPS 2025, ArXiv: 2410.04010]; `Khrulkov, V., et al. (2020). Hyperbolic Image Embeddings.` [CVPR 2020, ArXiv: 1904.02239]; code marlin-codes/HypLoRA.
* **File & Function**: `src/blme/tasks/geometry/delta_hyperbolicity.py` -> `DeltaHyperbolicityTask`
* **Critical Info**: Headline keys: `delta_rel_input_embedding`, `delta_rel_last_layer`, `delta_rel_min`. Declared invariant: `delta_rel_input_embedding`, `delta_rel_last_layer` to identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_delta_hyperbolicity.py::test_headline_invariant`); `delta_rel_min` to identity blocks (interior) (`tests/tasks/invariance/test_geometry_delta_hyperbolicity.py::test_headline_invariant`). delta grows with the number of points, so every cloud has 64 tokens. The estimator fixes the first point as the base point, as the release does, which bounds delta only to within a factor of 2 of its four-point value. The sink row at position 0 dominates hidden-state diameters, so the profile drops it. Prompts are the first 200 corpus passages of at least 1000 bytes; profile clouds are positions 1–63 of hidden states 1..L. Only position 0 is dropped: massive rows later in a prompt are kept (27 of 200 pythia clouds have one; dropping them raises interior layers 7–14%). On BOS models the BOS state is every prompt's base point (Llama input-embedding value 0.1274, 0.1408 without it).

## 49. Prompt-level intrinsic dimension (geometry_prompt_id)
* **What are we measuring**: The intrinsic dimension (ID) of the cloud formed by one prompt's token representations, at every layer, averaged over prompts; and, within the model, how strongly a prompt's ID tracks how surprising the prompt is to the model.
* **How are we measuring**: The released protocol of Viswanathan et al. Each prompt is tokenized without special tokens and truncated to its first 1024 tokens (capped at the model's context); its tokens at every HF hidden state after the embeddings (the last after the final norm) form one cloud per layer. Repeated rows are removed and GRIDE (DADApy `return_id_scaling_gride(range_max=64)`, BLME's port in `gride.py`) gives the ID at range scaling n2 = 4 (n1 = 2), the scale the paper reads. `prompt_id_profile` is the mean over prompts; `prompt_log_id_surprisal_pearson` is, per layer, the Pearson correlation across prompts between log ID and the prompt's mean surprisal (nats per token, the HF loss). Prompts are the first 256 WikiText-103 train articles of at least 8192 bytes, which holds 1024 tokens for any tokenizer under 8 bytes per token, so every model reads the same articles.
* **Hypothesis**: Viswanathan et al. find that the ID of a prompt's tokens rises from the first layers to a peak in intermediate layers and then falls, and that within a model log ID correlates with the prompt's surprisal (the release's arrays give 0.55-0.79 per layer for Llama-3-8B and 0.54-0.82 for Pythia-160M).
* **Citation/Paper**: `Viswanathan, K., et al. (2026). The Intrinsic Dimension of Prompts in Internal Representations of Large Language Models.` [TMLR 2026, ArXiv: 2501.10573]; `Denti, F., et al. (2022). The generalized ratios intrinsic dimension estimator.` [Sci. Rep. 12:20005]; code RitAreaSciencePark/token_geometry and DADApy.
* **File & Function**: `src/blme/tasks/geometry/prompt_id.py` -> `PromptIntrinsicDimTask`
* **Critical Info**: Headline keys: `prompt_id_peak`, `prompt_id_last_layer`. Declared invariant: `prompt_id_peak` to zero-padding the width, a global rescale and identity blocks (interior) (`tests/tasks/invariance/test_geometry_prompt_id.py::test_headline_invariant`); `prompt_id_last_layer` to zero-padding the width, a global rescale and identity blocks (interior, leading, trailing) (`tests/tasks/invariance/test_geometry_prompt_id.py::test_headline_invariant`). Each prompt runs through the model on its own and its per-layer IDs are computed before the next one, so no prompt's states are kept. Most of the cost is the CPU GRIDE of a 1024-point cloud per layer and prompt, computed with and without position 0. The release uses 2244 Pile-10K prompts. The ID depends on the number of points, so every prompt has 1024 tokens and a prompt that tokenizes shorter is dropped (`_meta_n_prompts_too_short`); models with a shorter context read fewer tokens (`_meta_prompt_tokens`), so compare them only with each other. Position 0 stays in the cloud, as in the release; `_meta_prompt_id_profile_without_first_token` drops it. Without special tokens a model trained with a BOS never sees it; `_meta_tokenizer_adds_bos` marks those models. A block before block 0 adds the embedding state and one after the last block the pre-norm state, and either can move the peak (`tests/tasks/invariance/test_end_of_stack_identity_blocks.py`); `_meta_prompt_id_peak_depth` moves when blocks are inserted. The surprisal correlation is a within-model statistic and says nothing by itself about differences between models. The release's ESS and TLE cross-checks are not ported.

## 50. FFN spectral utilisation (geometry_ffn_spectral_utilization)
* **What are we measuring**: How evenly each feed-forward network spreads the variance of its post-activation over its D = d_ff latent directions.
* **How are we measuring**: The paper's formulas (no code was released). Per layer, X is the input of the down projection (sigma(W_gate x) * (W_up x) for gated MLPs, act(W_in x) for GPT-2 and GPT-NeoX) over N tokens, and Sigma = (X - mu)^T (X - mu) / (N - 1) with eigenvalues lambda_1 >= ... >= lambda_D and p_i = lambda_i / sum lambda. Hard rank PR = (sum lambda)^2 / sum lambda^2; soft rank eR = exp(-sum p log p); their normalised forms (r - 1) / (D - 1); spectral concentration SC = (2 / D) sum_k (sum_{i<=k} p_i - k / D); SUI = the harmonic mean of the two normalised ranks; eDim = 1 + (D - 1) SUI. The headline keys are the layer medians (the paper's figures plot the layer median) of SUI, eDim, eR and PR; every quantity is also reported as a per-layer profile.
* **Hypothesis**: Jha & Reagen report an asymmetric spectral scaling law: as the FFN widens, the soft rank grows almost as a power law in D, while the hard rank grows sublinearly and with high variance, so wider FFNs mostly add low-energy directions and the dominant ones saturate early.
* **Citation/Paper**: `Jha, N. K., & Reagen, B. (2025). Spectral Scaling Laws in Language Models: How Effectively Do Feed-Forward Networks Use Their Latent Space?` [EMNLP 2025, ArXiv: 2510.00537]; no released code.
* **File & Function**: `src/blme/tasks/geometry/ffn_spectral.py` -> `FFNSpectralUtilizationTask`
* **Critical Info**: Headline keys: `ffn_sui_median`, `ffn_edim_median`, `ffn_soft_rank_median`, `ffn_hard_rank_median`. No key is declared size-invariant. The paper trains its own models on C4 and fits power laws across widths; it reports no single model-level score and does not state N. BLME uses N = 32768 tokens (`n_tokens`): the first passages of the library corpus with the tokenizer's defaults, at most 512 tokens each, the last one cut so N is exact. Every rank depends on N: the covariance has rank at most N - 1 (`_meta_n_nonzero_eigenvalues_profile`), so values are comparable only at the same N. Position 0 is included, as the paper uses all tokens; in pretrained models it can be a sink, so the spectrum without it is `_meta_*_without_position0`. Each layer needs a float64 D x D accumulator; layers run in consecutive groups that fit `memory_budget_gb` (default 8), with one pass over the same tokens per group. On BOS models the BOS row, identical in every passage, can dominate a layer (Llama: 72/99/44% of the variance at layers 0, 1, 15); without it the SUI median is +10% and the hard-rank median +11%.

## 51. Readout dual spectrum (geometry_readout_dual_spectrum)
* **What are we measuring**: How much the model's next-token distributions differ from one position to another, and how that difference is spread over the directions of the state the head reads, in a form that does not depend on how that state is parametrised.
* **How are we measuring**: For a softmax head z = s (W h + b), h is the natural parameter of an exponential family and mu = s W^T p its expectation parameter, and KL(p_x || p_x') + KL(p_x' || p_x) = (h_x - h_x') . (mu_x - mu_x') = (z_x - z_x') . (p_x - p_x') exactly. The Jeffreys dispersion `jeffreys_dispersion` = 1/2 E J over distinct pairs of positions = tr Cov(z, p) (nats; the logit form, exact for any head). The dual spectrum kappa_i = sqrt(eig_i(Cov(h) Cov(mu))) is unchanged by any invertible affine re-basing of h with the compensating head change (exactly in exact arithmetic; for the numerical range see Critical Info); `dual_coupling` = sum kappa (>= the trace, the Bures bound), `dual_coherence` = tr Cov(h, mu) / sum kappa in (0, 1], `dual_effective_rank` its Roy-Vetterli effective rank (and `dual_effective_rank_frac` that over d), `dual_tail_exponent` the decay of kappa over ranks 11-100. Rows are the word-final positions of the default corpus: the text read so far ends exactly at the end of a whitespace-delimited word (from the tokenizer's character offsets; a character split across tokens never qualifies, nor does the last token of a passage, which has no successor to check, nor a word that ends the text, which no whitespace follows), with position 0 and massive-activation rows excluded, N = 32 d rows. h is captured at the head's input; the head is recomputed in float32 and checked against the model's logits; the softmax and every moment are float64 and streamed.
* **Hypothesis**: The research memo of 2026-11-21 (section 4.2) predicts that, once the gauge of the read state is removed, final-layer geometry carries little beyond width and loss: D_J and coherence track bits per byte, and the dual effective rank is about 0.4 d. Random initialisation gives coherence near 1 and a dispersion near 0. The expected directions, D_J rising and coherence falling with capability, hold along a training run, not across models at a fixed loss: at a fixed loss, a larger D_J is over-confidence, not capability.
* **Citation/Paper**: BLME construct. Exponential-family duality: Amari & Nagaoka (2000), Methods of Information Geometry; the Bures coupling: Bhatia, Jain & Lim (2019) [ArXiv: 1712.01504]; dual coordinates of the softmax head: Park et al. (2026) [ArXiv: 2602.15293].
* **File & Function**: `src/blme/tasks/geometry/readout_dual_spectrum.py` -> `ReadoutDualSpectrumTask`
* **Critical Info**: Exploratory, not part of the paper core. Declared invariant at a fixed N to the readout gauge, zero-padding and isometric embedding of the read state (`tests/tasks/test_readout_dual_spectrum.py::test_size_invariant_entry`, 1e-10 on float64 models): every headline but the /d twin. The invariance is exact in exact arithmetic. Numerically, the kappa keys are computed from the two covariances, and a blind review (2026-11-21, gpt2, float64) found them held to about 1e-12 for dense re-basings A with cond(A) up to about 1e3 and drifting beyond about 1e4: 8e-5 relative at cond(A) = 7.7e4; at 2e7, 4% in `dual_coupling` and `dual_coherence` and 11% in `dual_effective_rank` (`jeffreys_dispersion`, which does not use the spectrum, moved 2e-10). Diagonal gains are removed exactly at any scale, by the per-coordinate balancing before the eigensolver. The models' own bases measured are far from the limit: on gpt2 cond(Cov h) is 2.8e9, against about 6e12, where the rank tolerance (e_max d eps) starts zeroing eigenvalues. Since 0.2.7 the result reports the conditioning of the two balanced covariances the eigensolver reads (Cov(h) and Cov(mu) after the per-coordinate balancing): `_meta_cov_h_eig_range` and `_meta_cov_mu_eig_range` give [smallest kept, largest] eigenvalue. `_meta_cov_h_condition` and `_meta_cov_mu_condition` give their ratio, the condition number on the kept subspace. `_meta_cov_h_eigs_zeroed` and `_meta_cov_mu_eigs_zeroed` count the eigenvalues the rank tolerance set to 0. A final LayerNorm puts the read state on a hyperplane, which zeroes one eigenvalue of Cov(h) in a float64 model; in a 16-bit model, rounding can lift it above the tolerance, and it then shows as a large condition number instead. `_meta_cov_condition_limit` = 1 / (d eps) is the condition number at which zeroing starts. The invariance of the kappa keys holds numerically only for well-conditioned re-basings, with cond(A) up to roughly 1e3-1e4. A covariance condition number near the limit means the small end of the spectrum is numerically unresolved. Under a final logit softcap (Gemma-2) `_meta_d_space_exact` is false: `jeffreys_dispersion` (the logit form) stays exact, but the d-dimensional kappa spectrum is a first-order approximation, and a coarse one: on gemma-2-2b (cap 30, run at N = 2 d) tr Cov(h, mu) is 41% of the exact D_J, and `dual_coherence` is 0.274 against 0.661 at the logit level (`_meta_dual_coherence_logit_level`). Exclude soft-capped models from comparisons of the kappa-based keys (`dual_coupling`, `dual_coherence`, `dual_effective_rank`, `dual_effective_rank_frac`, `dual_tail_exponent`). Untrained or random vocabulary rows also collapse the kappa keys: gpt2 with 1,000 added N(0, 0.02) head rows gives a dual effective rank of 2.99, against 213 without them (N = 8 d). Released checkpoints are unaffected (the padding rows of pythia-160m-deduped's head hold 6e-118 of the probability mass). The default pins N to 32 d rows, so a wider model reads more rows (`_meta_n_rows`, `_meta_points_per_dim`); the default corpus covers 32 d at every d <= 5120 (`_meta_n_target_met`), and a wider model gets fewer than 32 rows per dimension. `_meta_n_target_met` is computed before sink removal, so it can be true while `_meta_n_rows` is a few rows under the target; `_meta_points_per_dim` counts the rows after removal. Position 0 is never a row, so a tokenizer without BOS never scores a first word that is a single token: about 0.6-0.7% of word ends (99.3-99.4% are scored). Every position >= 1 is `_meta_*_all_positions` (on pythia-160m-deduped D_J 8.47 against 6.44 word-final, the mid-character byte positions the word-final rule removes). Sink rows are removed exactly from the streamed moments (`_meta_sink_rows_removed`). A tokenizer without character offsets gives NaN headlines (`_meta_word_final_reason`).

## Domain loss and paraphrase LiDAR

Both tasks accept a JSON panel through the per-task `panel_path` configuration. To run one task through the Python API, you can also pass just its rows as `dataset`. The study measures four disjoint blocks. Small fixtures can use a single block.

- `geometry_domain_bpb` reads a `documents` array. Each record has a unique `id`, a `domain` string, an integer `block` and raw `text`. Each block must cover the same domains. The task conditions on BOS (EOS fallback), scores every content token once, and divides summed negative log likelihood by log(2) times total UTF-8 bytes. The vocabulary normalization and log-loss sums use float64. It returns domain and block BPB, a macro-average, and per-document NLL, byte and token counts. [Thrush et al.](https://arxiv.org/abs/2409.05816)
- `geometry_paraphrase_lidar` reads a `triples` array. Each record has a unique `id`, an integer `block`, an `anchor`, a verified `positive` paraphrase and a same-topic `negative`. Each block needs at least three triples and the same number of triples. The task mean-pools the final content-token states, computes a regularized discriminant effective rank on positive and negative pairs, and returns RankMe and pooled-panel controls. The primary value averages log(rank / (groups − 1)) over blocks. The default ridge fraction is 0.01. [LiDAR paper](https://arxiv.org/abs/2312.04000)

Both tasks check that the same input text decodes exactly from the content tokens. Set `max_tokens` to include the document-start token. An unrepresentable or overlong record raises an error, so all model comparisons can use the same bytes.

A single panel file can contain both arrays.

```python
import blme

panel_path = "document_and_paraphrase_panel.json"
tasks = ["geometry_domain_bpb", "geometry_paraphrase_lidar"]
result = blme.evaluate(
    model_args="pretrained=gpt2",
    tasks=tasks,
    task_configs={task: {"panel_path": panel_path} for task in tasks},
)
```
